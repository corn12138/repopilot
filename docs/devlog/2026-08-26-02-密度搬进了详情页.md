# 密度搬进了详情页

P0 降噪（08-25-01）止步于列表层。交互评审 v0.2（docs/inception 本地）真机复核发现：
点开任何一个 Run，界面回到 P0 之前的世界。病根不是「事实太多」，是三个机制 ——
**同一事实没有唯一主场、审计语态铺满默认视野、设计内常态被渲染成常开警报**。
本片修 N2/N3/N4/N5 四处，照旧全是降层级不删事实，零 Core 改动。

## 改了什么

### N2 · 运行卡：判定与计量各归主场

原来一行最多 10 枚徽章：状态、失败归类、证据、gen-N、四个 `m/n` 计量、用量未知、耗时 ——
判定与计量同权重并排。而这些计量在顶栏用量面板（UsagePanel）里**本来就有第二份**，
状态与证据徽章在 ChatHead 里**也有第二份**。同一屏说两遍，就是"密"的直接来源。

现在：状态与证据徽章的主场是 ChatHead（选中 Run 时常驻），四项计量与墙钟的主场是
用量面板（顶栏 chip 点开），gen 收进卡片 hint 与 runId 并排。运行卡只保留别处没有的
判定：失败归类。

### N3 · 数据出站：报数常驻，账本收起

出站卡逐笔列出全部调用 —— 而同样这些调用在「对话」卡里已按轮呈现，一屏两遍。
现在报数留在卡片头（「N 次已发出 · M 次未发出」），出站同意与逐笔明细收进
「出站同意与逐笔明细 ▸」默认折叠；0 笔且无同意记录时不成卡，一行说清。
逐笔账本一条不少，只是不再是每次打开详情的默认视野。

### N4 · 「状态落后于事件」不再常开

从磁盘恢复的 Run 落后一拍是设计内的正常终局，之前却顶着黄徽章 + 黄横幅 + seq 编号 ——
真机三个历史任务**全部**如此。正常状态长期以警报形态出现，真警报就失去信号价值。

现在：restored + EVENTS_AHEAD 的徽章降为信息级「已从磁盘恢复」（落后细节进 title），
横幅并入恢复说明，seq 数字保留在小字里；**未恢复（可能还活着）的 EVENTS_AHEAD
仍是黄牌黄条** —— 降级只给设计内常态，不给真警报。

### N5 · 省略披露与轮次行：解释不该比被解释的更吵

省略披露曾用四行长句 + 枚举报数（`TOOL_CALL_RESOLVED×36`）解释折叠了 2 条常规事件。
现在报数一行常驻（位置不变，仍在时间线末尾），分类明细收进「省略明细 ▸」。
轮次行的 per-call token（`(in=12938 out=1485)`）收进 title —— 总量在用量面板、
逐笔在数据出站，行上不再第三遍；行上留模型名。

# 一本词典说到底

产品早就有完整的中文映射表（14 态 RunStatus、16 类失败、13 种排除原因），
但界面上仍到处裸写内部枚举：中文句子里嵌 `ACCEPTED_UNVERIFIED`、`R0`–`R4` 无解释、
证据页开头对操作者引用 `ASM-019 / SPK-010 / PRD §11.1`、终端块直接打印 `SUCCEEDED`。
两本词典并用，读者每句话都要切一次语言。这是交互评审 v0.2 的 N7；同片带上 N6
（恢复 Run 的文件面板）。执行红线一句话：**用户可见文本只用词典词，raw 进 title。**

## 改了什么

### N7 · 词典执行

- **ResolutionBadge 说人话**：`SUCCEEDED→成功`、`DENIED→被拒绝` 等，raw 进 title。
  `UNKNOWN_RECONCILING→「结果未知 · 对账中」`且从红色改为**紫色**（信号缺失，
  不是机器负向终局）—— 这正是 08-17 conformance audit 里"设计稿比代码做得对"的那条，
  红色会让用户误以为要去修它。终端块原本自绘的 raw 徽章统一改走 ResolutionBadge。
- **RiskBadge**：`R0`–`R4` 代号保留，语义进 title（只读 / 构建测试 / 需精确批准 /
  拒绝执行），来源即 commandRisk.ts 的分级注释。
- **补丁警告横幅**：「接受后 Run 终态是 ACCEPTED_UNVERIFIED，不是 SUCCEEDED」→
  「终态是**「已接受·未验证」**，不是「成功」」，raw 在 title 里。
- **验证块**：`BASELINE/POST_MUTATION` → 基线验证/改后验证，`PASSED/FAILED` → 通过/未通过。
- **证据页**：免责声明改为对操作者说的话（"不能证明换个厂商交叉审核就能降低缺陷 ——
  那需要密封 A/B 对照实验"），ASM/SPK 编号收进 title；北极星各行、终态分布、
  失败分类、审后现状全部走词典（DistTable 新增 translate，raw 键进 title）；
  `PASS→通过`。
- **失败分类词典**从 RunDetail 下沉到 common（`failureClassText`）—— 证据页也要用，
  一处定义两处消费。

### N6 · 恢复 Run 的文件面板：设计内状态不渲染成错误

原来打开恢复 Run 的文件面板必然撞上一段红字「文件树读取失败：该 Run 已从磁盘恢复，
工作区不再可用」—— 把设计内的必然状态渲染成故障，而 Core 的错误详情里自己就写着
出路（"只能查看导入时的快照原貌"）。现在照它说的做：restored 的 Run 直接以快照
通道打开文件树，面板顶部说明「隔离工作区已随进程结束回收 —— 下面是导入时的
快照原貌」。红字只留给真正的读取失败。顺带：↻/✕ 两个图标按钮补上中文 aria-label。

# 指标层只投影，不产生新事实

方向是拿一份 Agent 工程师的 JD 对照出来的：行业已收敛的七件事（运行时、评估、
Harness、上下文、工具集成、服务化、可观测）里，本项目六件要么已建成要么刻意冻结，
唯一的真缺口是**评估体系** —— 而这恰好也是自家文档里卡着一切 Deferred 决策的那块：
`ASM-019`（异构审核有没有用）Open、`SPK-010`（sealed A/B）Not authorized、
ADR-010 的证据栏写着"baseline / defect delta / 成本对照均不存在"。
评审定了，这一片就从它开工。第一块砖：**跨 Run 证据聚合**（`evidence.summary` + 证据页）。

## 先划清这块砖不是什么

差点把 sealed A/B harness 一起做了，动手前停住：`SPK-010` 的状态是
`Deferred / Not authorized`，TD-DEC-016 写明"SPK-010 需另行授权"。
授权边界内能做的是**只读聚合已经发生的事实** —— 观察，不实验。

这个边界不只是流程问题，是统计问题：观察性数据里"选了审核方的任务"和"没选的任务"
本身就不可比（谁会给难题配审核方？选择偏差），拿分布差异冒充 defect delta
就是拿相关性冒充因果。所以聚合层**结构上**不产出任何"审核有效/无效"字段，
`verified defect delta` 进的是 `notComputable` 清单，原因和解锁条件（SPK-010）写在条目里，
页面顶部的免责原话："它是观察性分布，不构成 ASM-019 的证据"。

## 这块砖是什么

`src/core/evidence.ts`：纯函数聚合，输入全部是平台已持有的事实 ——
每个 Run 的账本、append-only 事件、封存记录，加上 `egress.jsonl` 的逐笔出站清单。
产出 PRD §11 里平台事实撑得住的那个子集：

- **北极星 + 漏斗，强制同产出**。`Accepted Verified Patch Rate` 的分子是 SUCCEEDED
  （语义由 `setStatus` 不变式担保：接受 + 验证通过 + 覆盖未削弱），分母是
  **进入过 EXECUTING 的 Attempt**（事件流里数 `STATUS_CHANGED → EXECUTING` 的
  去重 attemptId）。PRD §11.1 的反美化条款照抄成类型结构：漏斗字段与北极星
  在同一个对象里，想只发布接受率得先改类型。
- **交叉审核观察面**：按审核方身份（判别联合）+ 厂商同异三态分组 ——
  轮次、verdict 分布（INCONCLUSIVE 单列，永不折进 PASS）、阻断发现数、
  指纹跨轮重复的 Run 数（no-progress 信号，指纹是平台算的）、结束原因分布、
  审后 Run 现状分布。质量数字全部来自平台观察，一个都不从 reviewer 自报计算。
- **成本**：账本合计 + 按 `ModelInvocationPurpose` 拆分（`egress.jsonl` 逐笔投影）。
  token 未知记未知轮次；被接受 Run 的均值旁边标着"样本里有几个含未知用量" ——
  均值可以给，均值的可信度也得给。
- **数据质量**：损坏的 Run 从所有聚合排除，但 `excludedFromMetrics` 如实报数；
  egress 日志的坏行数同样上报 —— 读不出的清单与"没出过站"必须可区分。

Renderer 侧加了「📊 证据」页（与设置页同级），jsdom 测试钉住三条展示纪律：
分母为 0 不渲染百分比、INCONCLUSIVE 带"不是通过"的说明、免责与 notComputable 可见。

## 最顺的部分：一条新事件都没加

动手前以为要补埋点，扫完发现**要的数早就都在**：

- `STATUS_CHANGED` 的 payload 是 `{from, to}` —— 漏斗的"进入执行"直接可数；
- `PATCH_DECISION` 带 `decision` —— 人工决定分布直接可数；
- `ATTEMPT_STARTED`（PRD-DIFF-003 补的）—— Attempt 计数直接可数；
- 账本的 `unknownUsageTurns`（"token 未知不折零"那次补的）—— 成本诚实性直接继承；
- `failureClass`（当时注释就写着"给统计、eval 和过滤用"）—— 失败分类直接可用；
- `egress.jsonl` 每笔带 purpose 和 token —— 按用途拆分直接可读。

这不是运气。是"先披露、后同意、再出站"、"省略要报数"、"append-only"这些规矩
在记账的时候就把口径钉死了。**指标层只投影已有事实**（PRD 成本行的原话：
"P1 Usage Ledger 只投影这些事实，不产生新指标来源"）—— 反过来说，
如果哪个指标算不出来，该修的是记录处的诚实性，不是在聚合层现编一个来源。

## 踩了什么坑

### 一、e2e 的聚合断言不能用等号

给交叉审核 e2e 补 `evidence.summary` 断言时想当然写了 `toBe(1)`。
红了才想起：data root 的 mock 是**每文件一个**临时目录，同文件里前面用例
persist 的 Run 会被后面用例的新 RunAuthority rehydrate 回来 ——
聚合接口"看见全部 Run"恰恰是它的正确行为。断言改成下界（`>=`）加特征查找
（按 reviewerKey + parity 找组）。聚合类接口的 e2e 断言天然要和
"世界里还有别的东西"共存，等号断言迟早变成别的用例的阻力。

### 二、`readonly` 的映射类型不能靠交叉类型去掉

`EvidencePurposeCost & { -readonly [K in keyof ...] }` 看着像"可写版"，
交叉类型里 readonly 仍然赢。要的是映射类型整体重建：
`{ -readonly [K in keyof T]: T[K] }`。运行时测试全绿、typecheck 红 ——
又一次证明这个仓库把 `pnpm typecheck` 和 `pnpm test` 分开跑是对的。

## 可复用的结论

- **观察和实验要在类型上分开。** 聚合层没有任何字段能表达"审核有效"，
  想说这句话必须先拿到 SPK-010 的授权和数据 —— 说不出口是结构保证的，不是自觉。
- **反美化条款可以编译进类型。** 北极星和漏斗在同一个对象里，"只发布好看的那半"
  需要先过一次显式的类型改动评审。
- **指标缺口是记录问题，不是聚合问题。** 聚合层发现算不出来，去修记录处，
  或者把它放进 notComputable 点名 —— 别在聚合层造新事实源。
- **聚合接口的测试断言用下界。** 它的职责就是看见一切，等号是在断言"世界里没别人"。

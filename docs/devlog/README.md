# 开发记录

RepoPilot 的开发日志。每篇独立成文，可以直接发到掘金 / 知乎 / 公众号。

## 命名与组织

```
YYYY-MM-DD-NN-短标题.md
```

按天分组，同一天内用 `NN` 排序。每篇聚焦**一个模块或一个决策**，不写流水账 ——
「今天干了啥」没人看，「为什么这么干、踩了什么坑」才有人看。

## 每篇的固定结构

| 段落 | 作用 |
|---|---|
| 开头 3 行 | 抛出一个具体问题，别铺垫 |
| 问题是什么 | 用真实代码/日志说明，不用假设 |
| 怎么解决的 | 关键代码 + 设计取舍 |
| 踩了什么坑 | **最有价值的部分**，写清楚错在哪、怎么发现的 |
| 可复用的结论 | 别人能带走什么 |

## 写作约定

- **不写没验证过的东西。** 每个「解决了」都要有测试或运行输出撑着。
- **坑要写全。** 包括当时的错误判断。写成一路顺风没人信，也没营养。
- **代码片段要能读懂。** 贴上下文，不贴光秃秃的函数体。
- **数字要真实。** 行数、耗时、测试数直接从仓库里取。
- 图用 mermaid（掘金原生支持），别截图。

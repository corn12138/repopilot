# 自述式的协议，接不进观察式的判据

有人问：我们做了一写一审（一个 Agent 写、另一个审），
A2A（Agent2Agent）不就是为 Agent 之间协作设计的协议吗，是不是正好？

查完之后结论是不接。但让我改主意的不是"A2A 不好"，
而是查的过程中发现我把两件事混在一起想了。

## 问题是什么

两天前我们刚把"作者写完了"这件事重新定义过一遍：

```ts
// 非 EXIT_ZERO 一律 seal=null，candidate 整笔丢弃，不看内容
// 只有 EXIT_ZERO 才允许平台去读那个目录
const now = listTree(input.candidate.path);
const changes = diffTrees(input.candidate.baseTree, now);
```

外部 CLI 自己吐的 `{summary, changedFiles, gaveUp}` 被标成 untrusted，
只展示、不驱动判定。整套设计的立场是一句话：**作者说写完了不算，目录差异才算。**

而 A2A 在完全相同的位置提供的是：

```
Task.status.state = COMPLETED
```

规范原文级的事实（我逐条查过 `a2a.proto` 与 spec）：

| A2A 对象 | 谁说了算 |
|---|---|
| `Task.status.state` | 远端 Agent 单方面断言，协议不提供任何验证机制 |
| `Artifact`（任务产出） | 无签名、无哈希、无 attestation、无 provenance |
| `provider.organization` | 纯自由文本 |
| `skills` | 规范原话：`largely a descriptive concept` |

再做一遍否定式核查 —— 对规范全文 grep 关键词，看它明确**不管**什么：

| 关键词 | 全文命中 |
|---|---|
| `sandbox` / `isolat` | 0 |
| `provenance` / `attest` | 0 |
| `train` | 0 |
| `residen` / `jurisdict` | 0 |
| `cost` / `billing` | 0 |

这不是控诉。`Opaque Execution` 是 A2A **明写的设计原则** ——
它承诺的正是"调用方看不见对面内部"。

所以第一层结论很直白：**A2A 的核心断言全是自述，我们的核心断言全要求可观察。**

## 但这个冲突其实能化解，这才是有意思的地方

我一开始以为这就是终点了。让另一个人（准确说是另一个 agent）
去尽最大努力论证"应该接"，它给出的化解方案是能成立的：

- 把 `COMPLETED` 降格成只能触发"**停止等待**"，不能触发"采用"
  —— 与现在 exit code 的地位完全相同（exit code 也是子进程自报的 1 bit，
  但它只能触发丢弃，谎报 0 换不到任何东西）；
- 强制把 `Artifact` 先落成**本地** candidate 目录，再走既有的
  `listTree` + `diffTrees` + `normalizeCandidate`。

这在机制上完全可行。我们的 `normalizeCandidate(ws, seal, candidatePath, runId)`
入参只有一个路径字符串，对"谁写的、在哪写的"零依赖 —— 架构确实留了这条缝。

**但化解完之后，A2A 的 Task 语义、Artifact 语义、状态机全部被弃用，只剩一个 HTTP 信封。**

那就不叫接协议，叫给自研传输套壳。

## 我混在一起的那两件事

真正的代价清单是这样的，我一开始把它们全记在 "A2A" 头上：

| 不变式 | 远程形态下 | 归因 |
|---|---|---|
| 一次性 synthetic HOME | **执行点消失**（没有本机进程就没有 HOME 可替换） | 离开本机 |
| 环境整份替换 | **执行点消失** | 离开本机 |
| 进程组整树终止 | **执行点消失**（取消从"副作用停止"退化成"我们不再听"） | 离开本机 |
| 出站披露的政策三项 | 协议无字段，永远 `UNKNOWN` | A2A |
| 预算作为**刹车** | 无法 kill 正在烧钱的进程树 | 离开本机 |
| 归一化整笔拒绝 / 平台算指纹 / schema 不放宽 / 收敛硬上限 / 模型不能宣称成功 / DLP | **全部 HOLDS** | 与传输无关 |

前三条不是"变弱"，是**没有落点**。而它们跟选哪个协议毫无关系 ——
换成自研 HTTP 一样要付。

最后一行才是这张表真正的信息量：**承载主要安全语义的那一批，全部与传输无关。**
这句话同时是"远程化没那么危险"的论据，和"换协议换不到什么"的论据。

最扎心的细节在取证手法上。现有测试是这么证明隔离的：

```ts
// 让子进程把 $HOME 写进文件，再断言它不是我们真实的 HOME
expect(readFileSync(join(dir,'home.txt'),'utf8').trim()).not.toBe(process.env.HOME);
// 注入 canary，断言子进程环境里没有它
expect(env).not.toContain('REPOPILOT_SECRET_CANARY');
```

**这两条断言在远程形态下一条都没有等价物。** 而 A2A 连一个可以声明隔离态势的字段都没有。
于是这个威胁在协议层：不可控制、不可声明、不可测试。

## 生态：这一层跑通的是另一个协议

这部分是查出来最意外的。逐个核实本机编码 Agent：

| | 暴露 A2A | 走 ACP |
|---|---|---|
| Codex CLI | 无（crate 树里没有 a2a 目录） | 是 |
| Claude Code | 无（官方文档 grep 零命中） | 是 |
| Cursor | 无（FR 挂近一年，官方从未回帖） | 原生 |
| Gemini CLI | 有，但包头自述 `experimental` | 原生 |

ACP（Zed 的 Agent Client Protocol）规范里**直接定义了 diff 内容类型**：

```json
{"type": "diff", "path": "<绝对路径>", "oldText": "<原文>", "newText": "<改后>"}
```

A2A 一个 code/diff 语义都没有 —— 官方 32 个样例里唯一沾边的 `github-agent`
只是自然语言包 GitHub REST API，连一个 code review demo 都没有。

所以"接 A2A 能省掉自己算 diff 吗"的答案是：**一点都没省**，
反而要多定义并维护一个自造扩展。

最强的外部佐证是 Google 自己：同一个 CLI 里，
"远程委派子 agent"给了 A2A（experimental），
"被人所在的客户端驱动着改代码"给了 ACP（正式文档）。
其内部 RFC 提议统一到 A2A，被一条反对意见挡住至今 ——
*A2A 的 Async First 与 Opaque Execution，与 IDE 需要的同步、人工可控交互冲突。*

顺便一个命名陷阱：大量文章说"ACP 已合并进 A2A、仓库已归档"，
指的是 **IBM 的 Agent Communication Protocol**；
与 Zed 的 **Agent Client Protocol** 同名不同物。搞混会得出完全相反的结论。

## A2A 唯一对得上的那个槽位

不是替换本机子进程，是**它够不到的地方**：组织内部自建的审核 Agent。

这条不是锦上添花。我们的审核方 vendor 来自一张本机静态描述符表，
**可选审核方总共两家、且都是通用模型**。而我们有一条挂了很久的假设：

> ASM-019：异构有界审核相比单 Agent + 人工审查能降低 verified defect —— 状态 `Open`

在这么小的样本空间里，这个 A/B 统计上几乎注定给不出结论。
所以"选手池太小"可能才是它长期 Open 的根因。

但顺序不能颠倒。这条推理有个前提没被验证：
**如果用现有两家选手都做不出正收益，加一层传输不会增加证据，只会增加面。**

所以我把它登记成一条新假设而不是一条需求：

> ASM-025：一写一审的质量收益不依赖把选手池扩大到本机两家 CLI 之外。
> 验证方式：先跑本机 sealed A/B；若无收益，再按失败分布判断是"机制无效"还是"选手池太小"，
> **只有后者才构成重开 DEC-018 的理由**。

## 踩了什么坑

### 一、我先问了"合不合适"，而不是"代价是什么、归给谁"

"A2A 合不合适"是个会得出模糊答案的问题形状。
换成"逐条列出不变式，判 HOLDS / WEAKENED / BROKEN，并写清机制"之后，
表格自己把答案分成了两列：**哪些是协议的账，哪些是远程化的账。**

这个区分改变了结论的可用性。如果笼统地说"A2A 与我们的立场天然不容"，
那么将来真需要远程审核方时，这句话会挡住一个其实正确的选项。
诚实的表述是：**离开本机执行模型的代价与协议选择无关**；
而在此之上，A2A 相比自研 HTTP 的增量价值（治理、IANA 注册、OAuth PKCE、
AgentCard 签名、统一错误码与版本协商）在**跨组织**场景下是正的。

### 二、让对立双方论证，比让人 review 有用

我让两个 agent 分别把"该接"和"不该接"论证到最强，各自必须引用取证结果、
并且最后必须写出对自己最强的反驳。

结果两边收敛了：**"该接"那一方在最后被要求给决策而不是辩护时，给的是"现在不接"。**
这种收敛比任何一方单独的结论都可信。

而且"该接"那一方为了论证"我们的护城河靠什么成立"，
去引我们自己那条 `拿不到结论就是拿不到 —— 记 INCONCLUSIVE，绝不当作"没有发现"` 的注释，
引着引着发现下游把它折掉了 —— 那是[上一篇](2026-08-21-01-没给出结论被显示成通过了.md)修的那个假绿。

**review 会顺着作者的意图读，论证会逼它检查意图有没有兑现。**

### 三、否定式核查比正向阅读值钱

读一份规范"管什么"，读完你会觉得它什么都管。
对着关键词 grep 它"不管什么"，五分钟就能定选型：

`sandbox` 0 命中 → 隔离要你自己解决且无法声明。
`provenance` / `attest` 0 命中 → 产物真实性没有任何协议支撑。
`train` / `residen` 0 命中 → 出站披露里那三个 `UNKNOWN` 永远变不成别的。
`cost` / `billing` 0 命中 → 委派出去的花费协议不管。

这四个零，比任何一段"A2A 是什么"的介绍都更能回答"它适不适合我们"。

### 四、决定要落在文件里，否则下次从头再查一遍

查完发现：`docs/` 全目录 grep `A2A` **零命中**。
也就是说这是个**未裁决项，不是已否决项** —— 我不需要推翻任何既有决策，
但也意味着下一个人问同样的问题时，会把这一小时重跑一遍。

所以结论落成了三样东西：一份独立评审文档（证据、逐条判定、七条实现纪律）、
一条 `DEC-018`（裁定 + Revisit Trigger）、一条 `ASM-025`（它的有效期绑在什么证据上）。

**Revisit Trigger 比结论本身重要。** "现在不接"如果不写清楚"什么情况下重开"，
半年后它要么变成教条，要么被人一句"生态成熟了"就推翻。

## 可复用的结论

- **自述式协议接不进观察式判据 —— 但要算清这笔账里哪一部分是协议的。**
  能在适配层封死的，说明护城河不依赖传输；封死之后协议只剩信封的，说明换它没收益。
- **对规范做否定式核查。** grep 它不管什么（隔离、来源、成本、保留、驻留），
  比通读它管什么更快定选型。
- **让对立双方论证到最强，并要求各自反驳自己。** 收敛出来的结论比单方结论可信；
  而且论证过程会顺手撞出跟议题无关的真 bug。
- **"没做过裁决"和"裁决过不做"要分清。** 前者是空白，后者是边界。
  空白不需要推翻任何东西，但会被反复重查。
- **写下 Revisit Trigger。** 一个不说明有效期的结论，
  要么过期后还在挡路，要么被一句"时代变了"随手推翻。

---

裁决：`REJECT_AS_CROSS_REVIEW_TRANSPORT / DEFER_AS_REMOTE_REVIEWER_CHANNEL`。
Requirement ID 仍 87 个、THR ID 仍 64 个 —— 这一轮没有新增任何实现面，
只有一条边界和它的有效期。

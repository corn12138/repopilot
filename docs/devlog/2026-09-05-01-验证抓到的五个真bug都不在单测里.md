# 验证抓到的五个真 bug，都不在单测里

三天前观察面板 MVP 入库时是「全绿 + selftest ALL PASS」。今天用户只说了一句
「继续，需要大量的验证」。这一轮没写新功能，只做验证 —— 结果抓到五个真 bug，
每一个都在单测全绿的情况下存在，因为它们只在**真实数据、真实规模、真实运行时**里显形。

## 一、先复跑三天前的东西：断言工具立刻叫了

`pnpm probe:journals` 三天后重跑：claude 17 条增量漂移（新 type `agent-setting` /
`continued-in` / `file-history-delta` / `token_usage_record`，一堆新键），codex 11 条 ——
而且**两家都判 BREAKING_DRIFT**。但 claude 版本没变（仍 2.1.258）。

违规明细只有三条：`bridge-session.ownerOrganizationUuid` / `ownerAccountUuid` 降级、
codex `user_message.client_id` 降级。都是面板根本不读的键。诊断：40 个文件的窗口里，
罕见 type `bridge-session` 碰巧每条都带那两个键，被归进了 required 层；换个窗口就"违规"。
**基线的 required 层是样本归纳，一条反例分不清"格式变了"和"上次样本太小"。**

### Bug 1：运行时守卫会把真实会话误判成「格式未知」

面板复用了同一份判据。按三天前的代码，今天这台机器上任何含 bridge-session 记录的
会话都会渲染成「格式未知」—— 为了一个不读的键把整段正文清空。这是设计错误，不是实现错误。

修法是把两件事拆开：**离线对照**（probe）继续看全部字段，破坏性漂移照旧判红并说清
"要么格式变了，要么上次过拟合，人看一眼版本号再重建"；**运行时降级**只看**面板消费键契约**
（`type` 是字符串、claude 的 user/assistant 有对象 `message` 且 `content` 可读、codex 的
`payload` 形状可读）—— 真的读不了才降级。基线出入进 `driftNotes`，在正文下方一行提示，
不阻断。基线扫描窗口 40 → 200 个文件，让 required 层的交集更接近真相。

## 二、把窗口扩到 200 个文件：heap OOM

### Bug 2：probe 把 400 个文件全部读进内存再归纳

`captureShape(vendor, fileLines[][])` 的签名就决定了调用方得先把所有文件读完。
40 个文件没事，200 × 2 家 = 400 个文件，`FATAL ERROR: Reached heap limit`。
改成 `Iterable`：调用方用生成器逐个读，任何时刻内存里只有一个文件的行。
数组也是 Iterable，19 个既有单测一个字没改。重建后：claude 200 文件 / 113503 条 / 1.7s，
codex 198 文件 / 115433 条 / 7.5s，两家对照 MATCH。

## 三、面板对真实项目干跑：两个数字不对

给 probe 加了第三个测试：用 `ObserverService` 对本仓库的真实会话逐个投影，报状态分布、
漂移提示频次、耗时。第一次跑：`会话 29（claude 30，codex 0/400，codex 首行读不出 400）`。

### Bug 3：codex 400 个 rollout 首行全部读不出

首行探测一次性读 16KB。量了 20 个最新 rollout 的首行：19–49KB，中位 46KB ——
`session_meta.payload` 带着 13 个键（含 base_instructions）。16KB 截成半截 JSON，
`JSON.parse` 失败，全部计成"读不出"。三天前那个 124 行的样本只是碰巧小。
改成按 64KB 块读到第一个换行，上限 2MB；超上限不猜，仍计读不出。修完：codex 命中 12/400、读不出 0。

### Bug 4：claude 30 命中只列出 29 —— 同名文件互相覆盖

`find` 一下项目目录：166 个 `.jsonl`，只有 16 个是顶层会话；150 个是
`<会话>/subagents/agent-*.jsonl` 子代理记录和多份同名 `journal.jsonl`。两个后果：
sessionId 只用 basename，`journal.jsonl` 撞名互相覆盖（30 → 29）；"最新 30 个"的名额被
子代理文件挤占，面板里列出来的"会话"其实是子代理片段。
修法：sessionId 改为 `vendor:相对扫描根的路径`（不含宿主绝对路径，仍不泄露位置）；
claude 扫描深度上限 1（顶层才是会话），深层文件**计数**上报（`claudeNestedSkipped`），
不是静默忽略。修完：claude 16、子代理/子文件未列 150 —— 与 `find` 的 166 逐个对上。

干跑最终数字：28 个会话 19664 条记录，OK 28 / FORMAT_UNKNOWN 0；enable 124ms；
单次 watch（整文件读取 + 投影）p50 12ms · p90 16ms · max 18ms。

## 四、真实 Electron 里再跑一遍：截图不会撒谎

selftest 加了观察面板一段：桥是否真挂上 window、真实 IPC 的负向路径（未授权
listSessions/watch → NOT_GRANTED，未知方法 / 多余字段 → BAD_REQUEST）、点底部按钮真渲染出
视图。两个 opt-in 变量：`REPOPILOT_SELFTEST_OBSERVE_PATH` 在服务层直接授权真实项目
（自检拿不到原生手势；生产路径的授权仍只有对话框一条），`REPOPILOT_SELFTEST_CAPTURE_DIR`
在每个阶段 `capturePage()` 落 PNG。

### Bug 5：授权来自推送时，视图不去拉会话列表

第一次跑：`FAIL 已授权态下找不到任何会话按钮`。截图 03 显示视图切到了已授权态，列表是空的。
视图只在「自己发起 enable 的响应」和「初始 status」两条路上拉列表；Main 侧推来的
`observer.state` 只改了 granted 标志。修法一行：推送到已授权就 `refreshSessions()`。
补了 jsdom 用例钉住。

顺带两条截图教训：`capturePage` 拍的是合成帧，DOM 已更新 ≠ 已上屏，不等 300ms 拍出来是上一帧；
28 个会话把镜像卡推出首屏，文字断言过了、人眼看不见 —— 列表限高可滚，截图前把镜像卡滚进视口。
最终一轮：selftest **ALL PASS**，投影截图里是真实会话的正文
（记录 520 · 显示 200 行 · 跳过头部 1894862 字节 —— 大文件尾读路径在真实数据上跑到了）。

## 五、其余验证资产

  文件消失静默、被截短重读；>4MB 尾读无坏行；codex 首行 48KB 可读 / 2.1MB 判读不出。

数字：新增 22 个测试，全量 73 文件 / 1302 测试（3 个 opt-in 跳过），typecheck 干净，selftest ALL PASS。
PRD ASM-027 / TD-ASM-021 做了当日补注（判据收窄、窗口扩容、OOM），本篇同步记录。

## 六、这一轮的教训

- 「全绿」证明的是"我想到的都对"。五个 bug 全部来自我没想到的维度：真实数据的形状分布、
  真实规模的内存、真实目录的嵌套、真实运行时的推送路径、真实屏幕的首屏。
- 样本归纳出来的 required 键不配当运行时判据。判据要写成"我需要什么"，不是"我见过什么"。
- 报数救了两次：`codex 首行读不出 400` 和 `claude 30 → 会话 29`，都是计数不对账才被看见的。
  静默过滤的话，面板会安静地少一家、少一个，谁也不知道。

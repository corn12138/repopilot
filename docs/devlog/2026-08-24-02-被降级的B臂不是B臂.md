# 被降级的 B 臂，不是 B 臂

上一片把观察层数清了（指标只投影，不产生新事实）。观察层结构上答不了的问题只剩一个：
**一写一审值不值**（ASM-019）。这只有实验能答。用户授权开发后，这一片做了两件事：
把 SPK-010 的实验协议冻结成文档（《SPK-010 实验设计 v0.1》），然后把 harness 建出来。

## 协议先冻结，判定规则写在跑之前

实验最容易烂在两处：跑完再定判据（事后挑结果），和样本不够硬说话。协议把这两条先钉死：

- **判定规则预冻结**（设计 §6）：质量净收益 ≤ 0 → ASM-019 记 Rejected 倾向、SPK-010 保持
  Deferred；只有"无收益且失败分布明确指向选手池太小"才构成 DEC-018 远程通道的重开理由。
- **样本门槛**：不足 20 case（PRD 靶值）的一切结果只能标 `PILOT / underpowered`，
  不得进 PRD/TD 的 Evidence 栏。报告里这句话是代码生成的，不是自觉。

主判据是**人工盲评的 verified defect delta**。机器能给的 pass@1（平台验证口径）照给，
但报告里 `humanBlindEval` 在盲评完成前就是字面量 `'PENDING'` —— 没有任何字段能提前替它说话。

## 臂完整性：三道闸，一道都不省

实验里最隐蔽的失效不是崩溃，是**臂悄悄变质**：CROSS_REVIEW 臂的审核方因为缺凭据/
同厂商/连接器不可用被产品逻辑降级成"不审核"，Run 照常跑完、照常产出补丁 ——
一个实际单写的观察被密封成 B 臂结果，A/B 从这一刻起就是假的。而且它错得很安静：
每个数字都是真的，只有分组是错的。

所以 runner 给 B 臂设了三道 fail-closed 闸：

1. **披露预览**里必须真的有 REVIEWER 目的地 —— 这直接站在上一片修的
   "预览镜像降级判定"上：降级在预览就显形，观察在发起前作废；
2. **创建后**扫事件流，出现"降级为不审核"NOTE 即作废（挡预览与创建之间世界变了）；
3. **跑完后**审核记录必须存在，否则不密封。

三道都抛 `ARM_INTEGRITY`，观察作废重来 —— 宁可少一个观察，不要一个错组的观察。

## 盲评的破盲面要先枚举

盲包设计时先问的不是"放什么进去"，是"**带什么进去就破盲**"：

- 发现清单：只有 B 臂有 findings，带上等于把臂写在脸上 —— 不进盲包；
- runId / 审核方 / 臂标识：不进；
- 验证结论：可能与臂相关，且评审对象是补丁本身 —— 不进。

最后盲包每条只有 `{label, case 标题, case 目标, unifiedDiff}`；
`label → 臂` 的钥匙单独落盘（文件名就叫 `DO-NOT-OPEN-BEFORE-JUDGING`）并带 digest。
测试里这是一条负向断言：盲包序列化后不得含 `CROSS_REVIEW` / `SINGLE_WRITER` /
`runId` / `moonshot` / `reviewer` / `findings` 任何一个字符串。

其余纪律照 TD §22 逐条落：每观察一个 fresh RunAuthority（零共享内存态）、
未设 `REPOPILOT_DATA_ROOT` 直接拒跑（selftest 的规矩）、harness 代批计划如实记
`autoApprovals`、补丁接受不发生（度量止于 AWAITING_PATCH_REVIEW 的平台事实）、
收敛与预算沿用产品不放宽。结果 append-only + 整体 digest，回读逐条校验：
篡改一个字段、混进一行坏 JSON，都以计数的形式出现在报告的可信度声明里。

## 踩了什么坑

### 一、共享的脚本数组被 shift() 掏空

2 case × 2 臂的端到端里，第二个 B 臂观察稳定拿到 `REVIEWER_UNAVAILABLE`。
查了半天审核方绑定，最后发现是测试自己的问题：审核方脚本写成了共享常量数组，
而 fetch 桩用 `queue.shift()` 消费队列 —— 第一个 B 臂把那个数组原地掏空，
第二次 `script(REVIEWER, reviewerPass)` set 进去的是**同一个空数组**。
实现方脚本恰好是工厂函数所以没事。修法：全部工厂化。

教训跟生产代码一条规矩：**被消费的容器不能共享**。测试基建里的别名 bug
与生产里的别名 bug 一样贵 —— 它烧掉的是"以为是审核方绑定坏了"的排查时间。

### 二、臂完整性最初只有跑完后那一道

第一版 runner 只在采集阶段检查 crossReview 是否存在。写测试时意识到：
降级发生在 task.create，等跑完才发现，白烧一整个观察的 token 和墙钟 ——
而上一片刚好把"披露预览镜像降级判定"修好了，B 臂的第一道闸等于免费。
基建的复利就是这么来的：那次修 CONSENT_STALE 死循环时没人想到实验 harness 会用它。

## 可复用的结论

- **实验臂的身份要验证到最后一刻。** 产品里合理的优雅降级，在实验里是数据污染；
  fail-closed 是唯一正确的失效方向。
- **盲评设计从破盲面开始枚举**，而不是从"想给评审看什么"开始。
- **还没有的证据用显式 PENDING 占位。** 字段缺席会被读成"不适用"，
  字面量 PENDING 才读得出"该做而未做"。
- **判定规则和样本门槛写在跑之前**，且让代码替你说"样本不够"。
- **测试脚本队列工厂化。** 会被 shift 的东西绝不共享。

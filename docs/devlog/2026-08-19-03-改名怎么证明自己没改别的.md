# 改名怎么证明自己没改别的

> 开发记录 · 2026-08-19 · RepoPilot

设计定档之后要把 v2 的配色接进来。第一步不是换颜色，是把 Renderer 从「13 个颜色变量」
改成「三层 token」：第 1 层 palette（具体值）→ 第 2 层 role（按用途命名）→ 组件只引用第 2 层。

批 0 把三层建起来了，但为了让 251 处引用零改动，旧名先当别名留着：

```css
--text-faint: var(--text-tertiary);
```

批 1 就是把这 251 处迁到角色名，然后删掉别名。**一次纯改名，不许改动任何一个像素。**

## 「不许改像素」怎么证明

最省事的做法是跑一遍测试、看一眼截图、说「没变」。但改名波及 223 处 CSS + 58 处 TSX 内联，
眼睛不是可靠的差分器。

所以写了个 20 行的脚本：把 `styles.css` 里所有 `var(--x)` 顺着 `:root` 的链解析到**最终字面值**，
输出规范化文本；改名前后各跑一次，`diff`。

```
814 条声明，解析结果逐字节相同，0 处解析不了
```

这份 diff 才是验收。它能抓到眼睛抓不到的东西：某个 `var(--border)` 手滑改成了
`var(--border-control)` —— 两者**值不同**，diff 立刻炸。

## 一个差点顺手做错的语义拆分

`--border` 有 38 处引用。看用法明显分两类：

- 分隔线：`.sidebar` border-right、`.chat-head` border-bottom、`.dock` border-top…
- 控件边：`button`、`select`、`.composer-box textarea`、`.chip`

第 2 层里正好有两个角色：`--border-hairline`（`#262e3a`）和 `--border-control`（`#3a434f`）。
"顺手把按钮映射到 control" 看起来是白捡的语义修正。

但两个值**不一样**。今天按钮用的就是 hairline；改成 control 是真的改像素。

所以批 1 里 38 处**全部**映射到 hairline，语义拆分留给批 V。判据很简单：
**一批只能有一种性质。**「零视觉变化」的批次里夹一个视觉改动，这批的验收就不成立了 ——
diff 一旦允许有"预期内的差异"，它就不再是差分器，而是一份需要人工解读的清单。

有两处是值不变的语义修正，做了：焦点环从 `--accent` 改走 `--focus-ring`（同值，语义独立）；
`.usage-track` 的 4px 轨道底新增 `--surface-track`（它用的是 hairline 的颜色，但它是**面**不是线）。

## 批 1 真正的产出是一个 0

```
组件层直接引用第 1 层 palette 的次数：0
```

这个数字是换皮能不能一步到位的全部意义。它意味着换成 warm 是改 `:root` 里 16 行，
而不是在 5853 行 Renderer 里找颜色。合同测试把它钉住了：

```ts
it('组件层只引用第 2 层角色，绝不直达第 1 层 palette', () => {
  const body = css.replace(/:root\s*\{[\s\S]*?\n\}/, '');
  expect([...body.matchAll(/var\(--palette-[a-z0-9-]+\)/g)].map((m) => m[0])).toEqual([]);
});
```

外加一条「13 个旧名不得复活」—— 旧名回来就意味着有人绕过了角色层。

## 但 58 处硬编码 hex 不会跟着换

`:root` 之外还有 58 处裸 hex（`#46262a` 红边、`#1e3358` 蓝底、`#34275a` 紫底…），
它们不走 token，warm 一换就会变成"暖底 + 冷边框"的半成品。这是批 2 的活。

反解了一遍，30 个不同的值里**只有 7 个**能用单一 α 解释（`mix(语义色, 表面)`，三通道 α 差 <0.06）：

| hex | 来源 | α |
|---|---|---|
| `#46262a` | mix(failed-fg, panel) | 22% |
| `#1e3358` | mix(blocked-fg, canvas) | 27% |
| `#1c3a24` | mix(verified-fg, canvas) | 26% |
| `#2a1a1d` | mix(failed-fg, canvas) | 13% |
| … | | |

**其余 23 个反解不出单一 α —— 是手挑的。**

这跟设计稿自己得出的结论一样（它当时也发现"旧 hex 全是手挑近似，反解 α 三通道不一致"）。
所以批 2 不是机械替换，是**重新推导**：定 α 参数、按公式重算全部淡底/淡边、
接受与旧手挑值的**可见偏差**，再让合成后的值过门禁。

值得记的是这条：**「≤1/255 偏差」这种验收在批 2 不成立**，因为从手挑改成公式必然产生可见偏差。
批 1 能用逐字节 diff 当验收，批 2 不能 —— 得换成"逐屏人核 + 合成后值过门禁"。
**验收方式要跟着改动的性质走，不能一路沿用。**

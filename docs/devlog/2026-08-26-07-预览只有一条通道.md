# 预览只有一条通道

交互评审 v0.1 #7 / v0.2 P1：文件预览此前有两条通道 —— 树内嵌 `<pre>` 预览
（单击）与编辑器标签（双击），同一份内容两套读取逻辑、两套 generation 门禁、
两个显示位置。单击/双击语义只建立了一半，树在 264px 侧栏里还要塞一个预览底仓。

## 改了什么

### 通道合一：单击 = 预览标签，双击 = 固定（IDE 惯例）

- 树单击文件 → 编辑器打开一个**预览标签**（斜体、tooltip 说明）；预览位全局
  至多一个，下一次单击原位复用 —— 浏览十个文件不会攒十个标签。
- 树双击、或双击预览标签本身 → **固定**（斜体消失）；固定标签不被复用。
- 树内嵌预览整体退役：`files.read` 从 FileTree 中移除，文件内容的唯一读取
  通道是编辑器面板 —— generation 门禁、CONFLICT 重试、刷新重读由它统一执行，
  一套纪律不再维护两份。树保留选中高亮，且只指向仍然存在的文件。

### 行为等价性（诚实清单：退役的每一条能力去了哪）

| 内嵌预览的能力 | 现在在哪 |
|---|---|
| 按 tree generation 读文件 + 归属校验 | Editor 同一纪律（Editor.test 既有覆盖） |
| Agent 改动后自动重读正在看的文件 | Editor refreshKey 重读（既有覆盖） |
| 文件在新一代消失 → 不显示旧内容 | Editor 重读报错如实展示，不静默保留旧内容 |
| 二进制/截断的诚实标注 | Editor 同规则（既有覆盖） |

对应移除 4 条只测内嵌预览的用例（FileTree.test ×2、FileTree.calm ×2），
其余树级纪律（A/B 竞态、上一代只读、错误/空态区分）原样保留。

## 测试

App.layout.test 新增全链路：单击开斜体预览 → 换文件复用同一位置（标签数不变）→
双击标签转正 → 新预览位可用 → 树里双击直接固定；并断言树内不再渲染
`.filepanel-viewer`。Editor.test 标签夹具升级为 {path, pinned}。

61 文件 / 1050 测试全绿，typecheck 干净，selftest ALL PASS。

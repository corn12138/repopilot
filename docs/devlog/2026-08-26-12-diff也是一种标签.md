# diff 也是一种标签

交互评审 v0.2 P2 的最后一片（v0.1 §4 目标 IA 里的原话：「diff 也是一种标签」）。
此前补丁改动只能在补丁审查卡里逐文件展开看 —— 想对照现状代码、想把某个文件的
改动留在手边，都做不到。

## 改了什么

- 编辑器标签长出第二种身份：`EditorTab = file | diff`。file 照旧走 files.read
  的 generation 门禁；**diff 标签的内容是封存补丁的一份拷贝** —— 补丁不可变，
  拷贝即事实，不走 IPC，也没有"刷新"（封存物没有新版本，界面如实不提供）。
- 补丁审查卡每个文件行加「在编辑器打开」：± 前缀标签名、「补丁 diff」徽章、
  DiffView 正文、截断如实标注。id 用 `diff:` 前缀 —— 同一个文件的"现状"与
  "改动"可以并排开着对照。
- diff 标签始终固定（不占预览位）；打开时全屏视图退场、收起态解除 ——
  与"打开文件"同一套显式表达。
- 顺带修一句过期文案：恢复态横幅还写着「工作区文件树不可用」，而 N6 之后
  文件树已回落快照原貌 —— 改为如实描述。

## 测试

Editor：diff 标签零 IPC、±/徽章/无刷新按钮、同路径 file+diff 并排互不干扰。
RunDetail：文件行入口回传 path/diff 且不折叠该行（summary 默认行为被拦下）、
不接线时无入口。

62 文件 / 1061 测试全绿，typecheck 干净，selftest ALL PASS。

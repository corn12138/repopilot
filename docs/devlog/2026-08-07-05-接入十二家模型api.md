# 接十二家模型 API，抄一个开源 CLI 的设计

> 开发记录 · 2026-08-07 · RepoPilot

第一版模型接入是这么写的：三个适配器，每个硬编码自己的 origin，
API key 只从环境变量读，改模型要重启应用。

跑通了，但用起来能把人逼疯。这篇讲怎么参考
[neovate-code](https://github.com/neovateai/neovate-code) 的 provider 设计重写它，
以及哪一处我**故意没抄**。

## 第一版为什么难用

```ts
export const anthropicAdapter: ModelAdapter = {
  providerId: 'ANTHROPIC_OFFICIAL',
  origin: 'https://api.anthropic.com',        // 写死
  credentialEnvVar: 'ANTHROPIC_API_KEY',
  defaultModelId: 'claude-sonnet-4-5',        // 写死
  async call(req, ctx) {
    const res = await fetchJson(`${this.origin}/v1/messages`, /* ... */);
  }
};
```

三个问题：

1. **接不了中转站。** origin 写死，国内常用的各种代理地址全都进不来。
2. **换模型要改代码或者重启。**
3. **凭据只认环境变量。** 用户得先 `export` 再启动应用 —— 桌面应用这么搞很奇怪。

## 参考对象的设计

那个 CLI 的 provider 是一个纯数据描述符：

```ts
// src/provider/providers/types.ts
export interface Provider {
  id: string;
  env: string[];        // 凭据环境变量
  name: string;
  apiEnv?: string[];    // base URL 覆盖变量
  api?: string;         // 默认 base URL
  doc: string;          // 去哪拿 key
  models: Record<string, ProviderModel>;
  apiFormat?: ApiFormat;
  options?: { baseURL?: string; apiKey?: string; /* ... */ };
}
```

配一个具体的：

```ts
// src/provider/providers/deepseek.ts
export const deepseekProvider: Provider = {
  id: 'deepseek',
  env: ['DEEPSEEK_API_KEY'],
  name: 'DeepSeek',
  api: 'https://api.deepseek.com',
  apiEnv: ['DEEPSEEK_API_BASE'],
  doc: 'https://platform.deepseek.com/api-docs/pricing',
  models: { 'deepseek-chat': {}, 'deepseek-reasoner': {} },
};
```

这样一共 33 个 provider，加一个只是往数组里加一条。

四个值得抄的点：

### 1. 解析优先级明确

```ts
// utils.ts:36-48
export function getProviderBaseURL(provider: Provider) {
  if (provider.options?.baseURL) return provider.options.baseURL;   // 配置
  for (const env of provider.apiEnv || []) {
    if (process.env[env]) return process.env[env];                  // 环境变量
  }
  return provider.api;                                              // 默认
}

// utils.ts:50-65
export function getProviderApiKey(provider: Provider) {
  if (provider.options?.apiKey) return provider.options.apiKey;
  for (const env of provider.env || []) {
    if (process.env[env]) return process.env[env];
  }
  return '';
}
```

**配置 > 环境变量 > 默认**。简单直白，用户能预测。

### 2. 按协议方言分派适配器，不按 provider

```ts
// utils.ts:144-188
switch (apiFormat) {
  case ApiFormat.Anthropic: return createAnthropic({ baseURL, apiKey }).chat(modelId);
  case ApiFormat.Responses: return createOpenAI({ baseURL, apiKey }).responses(modelId);
  case ApiFormat.Google:    return createGoogleGenerativeAI({ baseURL, apiKey })(modelId);
  default:                  return createOpenAICompatible({ baseURL, apiKey })(modelId);
}
```

33 个 provider，4 种协议实现。这是关键的解耦 —— 我第一版是「3 个 provider = 3 个适配器」，
线性增长。

### 3. 内置表 + 用户配置合并，配置优先

```ts
// model.ts:78-89
function mergeProviders(base: ProvidersMap, override: Record<string, ProviderConfig>): ProvidersMap {
  const result = { ...base };
  for (const [providerId, config] of Object.entries(override)) {
    result[providerId] = defu(config, result[providerId] || {}) as Provider;
  }
  return result;
}
```

### 4. 缺省值兜底

```ts
// model.ts:274-310 normalizeProviders
if (!normalized.id) normalized.id = providerId;
if (!normalized.name) normalized.name = providerId;
if (!normalized.apiFormat && !normalized.createModel) {
  normalized.apiFormat = ApiFormat.OpenAI;    // 不写就当 OpenAI 兼容
}
```

用户加自定义 provider 时只需要填 id + api，其余全有默认值。

## 我照着重写的部分

适配器改成按 wire 协议划分：

```ts
export interface ModelAdapter {
  readonly wire: 'anthropic' | 'openai';
  call(request: ModelRequest, ctx: AdapterCallContext): Promise<ModelResponse>;
}

const ADAPTERS: Record<'anthropic' | 'openai', ModelAdapter> = {
  anthropic: anthropicAdapter,
  openai: openAiWireAdapter,
};
```

一个 openai 适配器服务**所有**兼容端点。去哪由 gateway 解析后传进来：

```ts
export interface AdapterCallContext {
  readonly apiKey: string;
  readonly modelId: string;
  readonly signal: AbortSignal;
  /**
   * 本次调用的完整 base URL（含版本路径）。
   * 已冻结的 Attempt 用的是**冻结当时**的值。适配器只在其后拼端点，不自己决定去哪。
   */
  readonly baseUrl: string;
}
```

内置 12 家：Anthropic、OpenAI、DeepSeek、Moonshot、智谱、阿里百炼、火山方舟、
硅基流动、魔搭、OpenRouter、AIHubMix、xAI。

## 差点写错的一个坑：`/v1` 不是通用的

第一版我的适配器是这么拼的：

```ts
await fetchJson(`${origin}/v1/chat/completions`, /* ... */);
```

看起来没问题，OpenAI、DeepSeek 都是这个形状。但把国内几家的地址列出来：

```
OpenAI    https://api.openai.com/v1
DeepSeek  https://api.deepseek.com/v1
智谱      https://open.bigmodel.cn/api/paas/v4     ← 不是 /v1
火山方舟  https://ark.cn-beijing.volces.com/api/v3  ← 不是 /v1
阿里百炼  https://dashscope.aliyuncs.com/compatible-mode/v1  ← 前面还有一段
```

硬拼 `/v1` 接后三家会直接 404。

正确做法是描述符里存**完整 base URL 含版本路径**，适配器只拼端点：

```ts
await fetchJson(`${ctx.baseUrl}/chat/completions`, /* ... */);
```

那用户只填个域名怎么办？规范化的时候补，但**只补这一种情况**：

```ts
export function normalizeBaseUrl(raw: string): string {
  const trimmed = raw.trim().replace(/\/+$/, '');
  if (!trimmed) return trimmed;
  try {
    const url = new URL(trimmed);
    // 只填了域名（没路径）→ 补 /v1，绝大多数中转站是这个形状
    if (url.pathname === '' || url.pathname === '/') return `${url.origin}/v1`;
    // 带路径的一律原样保留 —— 智谱 /api/paas/v4、火山 /api/v3，猜不得
    return `${url.origin}${url.pathname.replace(/\/+$/, '')}`;
  } catch {
    return trimmed;
  }
}
```

**能猜的猜，不能猜的绝不猜。** 这条规则比「统一加 /v1」或者「一律不加」都实用。

## 故意没抄的一处

那个 CLI 的登录流程最后一步：

```ts
// src/slash-commands/builtin/login.tsx:342-351
const result = await bridge.request('config.set', {
  cwd,
  isGlobal: true,
  key: `provider.${selectedProvider.id}.options.apiKey`,
  value: apiKey,
});
```

**API key 明文写进全局 JSON 配置文件。**

对 CLI 来说这是合理取舍：跨平台、零依赖、用户自己就是操作者。
但桌面应用有系统钥匙串，没理由不用。

改成 Electron `safeStorage`：

```ts
function persist(store: Store): void {
  mkdirSync(dirname(FILE), { recursive: true });
  const tmp = `${FILE}.tmp`;
  writeFileSync(tmp, safeStorage.encryptString(JSON.stringify(store)), { mode: 0o600 });
  renameSync(tmp, FILE);
}
```

`safeStorage` 的加密密钥由 macOS 钥匙串托管，密文文件被拷走也没用。

配套的边界：

- **Main 进程**：唯一能解密的地方，负责落盘和注入
- **Core 进程**：只在**内存**持有，不写库、不写配置、不进事件；重启即丢，由 Main 重新注入
- **Renderer**：只看得到来源（`APP` / `ENV` / `NONE`）和末四位

```ts
credentialHint: effectiveKey ? `…${effectiveKey.slice(-4)}` : null,
```

末四位是为了让用户确认「配的是哪把 key」，又不至于泄露。

另外那个 CLI 的 provider DTO 会把整个 `options`（含 apiKey）返回给前端
（`nodeBridge/slices/providers.ts:337-415`）—— 这个也没抄，我们的 DTO 是字段白名单。

## 覆盖了官方地址要说出来

用户填了自定义 API 地址，数据流向就变了。这件事必须显式：

```ts
/** 数据会不会经过第三方：中转站，或用户把官方地址改掉了 */
export function isRelay(d: ProviderDescriptor, origin: string): boolean {
  return d.kind !== 'OFFICIAL' || origin !== d.api;
}
```

UI 上是一个黄色的「经第三方」标记 + 一行说明：

> 你的代码上下文会经过这个第三方。

不是拦着不让用 —— 中转站在国内是刚需。但**用户得知道自己的代码要发去哪**。

还有一条容易忽略的：已冻结的 Attempt 用**冻结当时**的地址。

```ts
const response = await adapter.call(input.request, {
  apiKey,
  modelId: resolution.modelId,
  // 用**冻结时**的地址，而不是当前配置 —— 运行中改设置不能改变已在飞的 Attempt
  baseUrl: resolution.origin,
});
```

否则你在设置页改个地址，正在跑的任务下一次调用就悄悄发去了别的地方。

## 验证

自检走 UI 完全相同的路径，跑完自动还原：

```
初始           → source=NONE  model=claude-opus-5  origin=api.anthropic.com/v1  relay=false
存入 key 后    → source=APP   hint=…1234           enabled=true
改模型+覆盖    → model=claude-opus-5  origin=relay.example.com/v1  relay=true
自定义 provider → 共 13 个 · kind=CUSTOM · origin=relay.selftest.example/v1 · wire=openai
删除自定义      → 剩 12 个
重名被拒绝      → {"code":"BAD_REQUEST","message":"anthropic 与内置 provider 重名"}
还原后          → source=NONE  origin=api.anthropic.com/v1  relay=false
```

最后一行是自检的自律：**测试不能留下持久化改动**。第一版忘了还原 modelId，
跑完之后用户的配置就被改成 `claude-opus-5` 了。

## 可以带走的

1. **把 provider 做成纯数据。** 加一家的成本应该是「往数组里加一条」，不是「写个新适配器」。
2. **按协议分派，不按厂商。** 33 个 provider 用 4 个实现就够了。
3. **base URL 存完整路径。** `/v1` 不是通用后缀，硬拼会在国内厂商上全线 404。
4. **能猜的猜，不能猜的报错。** 只填域名补 `/v1`，带路径的原样保留。
5. **抄开源代码要看清它的场景。** CLI 把 key 写明文配置是合理的，桌面应用不是。
6. **改配置不能影响在飞的请求。** 冻结时的值要一路带下去。

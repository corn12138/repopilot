## 一、标题那件事：授权怎么给

设计时想当然的流程是「渲染层把当前项目的路径递给 Main，Main 去对应目录 tail 日志」。
写到一半撞上 `domain.ts` 里 `ProjectRef` 的注释：**宿主绝对路径只存在于 Core，
永不投影到 Renderer** —— 渲染层手里只有安全展示值，它根本递不出路径。

这不是障碍，是提示。翻到 `project.pick` 的实现：原生目录对话框由 Main 弹出，
路径从对话框产生，Renderer 全程摸不到。观察授权照抄这个形态：
**`observer.enable` 的 payload 是空的**（schema 层面就不收路径），Main 弹
「选择要只读观察的项目目录」对话框，用户选中的那一下就是授权本身。
DEC-020 要求的「按项目显式授权」拿到了它的最强实现 —— 授权不是一个可以被
伪造、被注入、被搬运的参数，是一次 OS 手势。取消对话框 = 什么都没发生。

## 二、独立通道：Core 全程不知情

TD-DEC-022 (a) 说工位/观察是用户能力面、不进 authority 链。落地形态：

- `OBSERVER_CHANNEL`（`repopilot:observer:request/event`）与 Core 契约**物理分离**，
  preload 里是第二座桥（`repopilotObserver`），没有 epoch —— 观察状态活在 Main，
  Core 重启与它无关；
- 授权、监视游标、会话映射全部只活在 Main 内存：应用重启即消失。授权要不要
  持久化、按什么粒度，是 Q-027 的未决问题 —— **未决就不落盘**；
- 撤销即清除：`disable` 同步清授权、清映射（含宿主路径）、清监视游标，
  Renderer 侧同步清投影 —— 两边都不留残影，测试钉着；
- 轮询定时器只在真的有会话被监视时存在：面板关着 = 零 IO。

## 三、上午的断言工具，晚上成了运行时守卫

`journalShape` 新增 `recordShapeViolations`：单条记录 vs 基线必现键。观察服务
逐条过它，任一违规 → 整个会话 `FORMAT_UNKNOWN`：正文清空，只报计数与违规键名，
面板上直接给出重建基线的命令。**同一份已提交基线、两个消费者**（probe 离线对照 +
面板在线守卫），漂移语义只有一份，不会各说各话。宁可不读，不可错读。

## 四、测试取材的一个小纪律

服务层测试如果用「符合基线的完整记录」做正文 fixture，就把断言焊死在基线的
具体键集上 —— 基线重生成一次，测试烂一片。取材规则改成：

- 正文行用**基线不认识的 type**（未知 type 不定罪，投影仍 OK）；
- 降级用例用**基线认识但缺必现键**的光杆记录（`{"type":"user"}` 必然违规）。

断言只依赖「基线认识 `user` 且必现键不止 `type`」这一条极稳的性质。

改动弄进主线，今天仍然只有正常任务流程一条路。

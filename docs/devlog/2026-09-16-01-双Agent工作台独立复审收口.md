# 双 Agent 工作台独立复审收口

2026-09-16 的第二次独立复审推翻了“剩余只有外部证据”的判断，并用 6 个负向反例把问题收成
N01–N08：派发后记账、跨项目串会话、跨 cycle finding 失真、Codex Key 没有建立 app-server
身份、live/replay 乱序、工作台缺权威动作与预算、续期复用 cycle、标题和注意事件身份不完整。

本轮按风险顺序完成实现，并把反例迁入正式测试。离线代码缺口已经关闭；真实供应商消息、中断、
角色互换仍因没有授权 Key 保持 Blocked。Codex journal 字段基线仍有红灯，也没有用更新快照把它抹绿。

## 事实链先于界面

模型 API 和外部 CLI 现在都在真正派发前先写 `DISPATCH_INTENT`，再同步持久化 Task 预算。
状态落盘失败会回滚未派发轮次，adapter/子进程零调用；每次 transport retry 单独占账，token 结算不重复
加轮次。503 后进入退避再取消时，最后一条 `NOT_SENT` 不会覆盖已经发生的派发事实。

finding lifecycle 改为按审核时间归并：解决声明只作用于已经存在的问题；同 fingerprint 后续重现会
重新 `OPEN`。续期首审带入当前未解决问题，既没复述也没显式解决时直接转
`REVIEWER_INCONCLUSIVE`，空 PASS 不能清账。用户若仍接受未解决项，理由继续绑定当时 patch digest。

每次用户续期生成新 cycle。Task 的审核/整改累计只增不清，cycle 内计数从零开始；reviewId 来自实际
审核记录。两循环 e2e 同时断言 round 累计连续、cycle 分开、reviewId 不复用。

## 工作位与认证边界

Workbench protocol 升到 v3。Main 用 `projectId` 校验 handle owner；Renderer 过滤 foreign list、
session.updated 和 reconnect 结果，项目切换清空草稿、消息与 epoch。回放和活事件进入同一份按
`eventSequence` 排序的账本，因此先到的 B 与后回放的 A 会稳定显示为 AB。

Codex 只准入固定验证版本。未知版本完成 initialize/版本识别后停止，不绑定 Key、不创建 thread。
准入版本使用 `account/login/start(type=apiKey)` 与 `account/read` 建立身份，隔离 CODEX_HOME 只写
`cli_auth_credentials_store="ephemeral"`；Key 不写入临时 auth 文件。零消息探针不把“能建 thread”
冒充成“真实模型已认证”。

工作台现在直接消费 Core 的角色、cycle、当前 2 审 1 改、Task 累计、自修复与未知用量投影，
并显示 managed session 的错误正文。任务详情抽屉复用现有 RunDetail，因此计划审批、交接继续、
停靠/模式、finding、覆盖弱化、验证和补丁决定仍由 Core 原入口处理，没有给聊天工作位写仓权限。

## 标题与注意事件

Observer protocol 升到 v4。本地别名按授权项目 + sessionId 存在 Renderer localStorage，优先于源标题，
不改源日志。标题按 Unicode code point 截断，并报告真正删掉的字符数。注意队列使用机器完成记录的
稳定 hash；只追加无关元数据不会让“已看过”失效，同名 sessionId 也不会跨项目复用别名或处置。

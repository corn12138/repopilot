# 时间线有了章节

交互评审 v0.2 P2 第一片：时间线的两处结构化 —— 相位锚点（v0.1 #6）与
终端输出行数上限（N10）。附带一条真机抓出来的假绿修复。

## 相位锚点：分组结构，不是又一条消息

进入规划/执行/验证/交叉审核的 `STATUS_CHANGED` 此前被当作"常规事件"折叠进
省略报数里 —— 用户看到的是「时间线省略了 3 条事件」，而不是"现在读到哪个阶段"。
现在它们渲染为安静的分隔行（`role="separator"`，短横线 + 小字标签 + 时间），
原始 summary 收进 title。终态与待决状态仍是完整的状态行，不降级。

省略机制随之简化：相位事件不再是省略（它们**被渲染了**，且比原来更显眼），
「展开这 N 条 / 重新折叠」按钮与 `recoverable` 通路失去唯一的供给方，一并退役；
其余省略类型（正文不可恢复的）照旧报数 + 明细折叠。锚点顺序忠于事件流 ——
真机上未验证模式的 Run 就是 CREATED → EXECUTING → PLANNING，锚点如实反映。

## 终端行数上限：折叠 + 报数

真机实测单个终端块可达 ~1900px。现在超过 14+4 行的输出默认前 14 行，
按钮报出剩余行数（「还有 26 行 —— 展开全部」），可展开可收回；
少量超出不折 —— 为省两行放一个按钮比两行更吵。命令输出、run_command 预览、
工具预览三处统一走 `TermOutput`。顺带把命令终局的判别联合说人话
（`EXIT_NONZERO` → 非零退出，raw 进 title —— N7 同一红线）。

## 一条假绿：全角括号

轮次行 token 进 title（08-26-02 的 N5）用的正则只匹配半角 `(in=…)`，
而 Core 的真实 summary 是**全角**`（in=…）`—— 这条降噪在真机上从未生效。
测试也用半角构造事件，与实现互相印证成了假绿。真机走查抓到后：
正则改为全半角都认，测试同时钉两种括号。教训写在注释里 ——
**夹具的字面量要抄真实数据，不要抄实现的想象**。

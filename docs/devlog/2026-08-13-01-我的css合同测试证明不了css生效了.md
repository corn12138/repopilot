# 我的 CSS 合同测试，证明不了 CSS 生效了

> 开发记录 · 2026-08-13 · RepoPilot

这一轮要做的是「让等待、更新、失败看起来不那么生硬」。动效、对比度、焦点环、
`prefers-reduced-motion` —— 全是视觉的东西。我给它们写了测试：

```ts
it('入场动效落在 120–160ms 区间内', () => {
  const durations = [...css.matchAll(/animation:\s*rp-enter\s+(\d+)ms/g)].map((m) => Number(m[1]));
  for (const ms of durations) {
    expect(ms).toBeGreaterThanOrEqual(120);
    expect(ms).toBeLessThanOrEqual(160);
  }
});
```

绿了。然后我在文件头写下这段话：

```ts
/**
 * 边界要说清楚：jsdom 不加载也不应用外部样式表，所以这里断言的是
 * **样式表声明了什么**，不是"某个浏览器真的这样渲染了"。
 */
```

写的时候是诚实的。但写完我就意识到：这条测试全绿的同时，
CSS 可以完全没被应用、`.rp-enter` 可以拼错、`:focus-visible` 可以被后面的规则盖掉，
它一个都发现不了。**我测的是我自己写的那个字符串。**

## jsdom 拿不到的两样东西

不只是样式表。跟随滚动那部分同样有洞：

```ts
// useStickToBottom
const distance = element.scrollHeight - element.scrollTop - element.clientHeight;
const next = distance <= thresholdRef.current;
```

jsdom 里 `scrollHeight` 和 `clientHeight` 恒为 0，`scrollTop` 的 setter 是空操作。
我要测「用户往回读时不抢滚动」，只能自己把这三个属性装上去：

```ts
function installScrollMetrics(element, initial) {
  const box = { ...initial, scrollTop: 0 };
  Object.defineProperty(element, 'scrollHeight', { get: () => box.scrollHeight });
  Object.defineProperty(element, 'clientHeight', { get: () => box.clientHeight });
  Object.defineProperty(element, 'scrollTop', {
    get: () => box.scrollTop,
    set: (v) => { box.scrollTop = v; },
  });
  return box;
}
```

这测得了**跟随逻辑**（距底超过阈值时 `scrollTop` 一动不动、未读数准确、
换 Run 时计数不跨实体继承），测不了**真实滚动几何**。
两件事都是真的：逻辑测试有价值，而且它挡住了真的 bug；但它撑不起
"这个容器真的能滚"这句话。

## 补上：让真实的 Chromium 来量

自检本来就会拉起完整的 Electron，加载真实的 Renderer，跑真实的 CSS。
既然那个浏览器已经在那儿了，就让它来回答。

```ts
const probe = document.createElement('div');
probe.className = 'rp-enter';
document.body.appendChild(probe);
const enter = getComputedStyle(probe);   // 计算样式，不是源文件里的字面量
```

对比度也用**计算后**的颜色算，而不是源文件里的 hex：

```ts
function parseColor(value: string) {
  const rgb = /rgba?\(\s*(\d+)\s*,\s*(\d+)\s*,\s*(\d+)/.exec(value);   // 计算样式返回 rgb()
  ...
}
```

`prefers-reduced-motion` 是媒体查询，只有真浏览器 + CDP 能模拟：

```ts
await webContents.debugger.sendCommand('Emulation.setEmulatedMedia', {
  features: [{ name: 'prefers-reduced-motion', value: 'reduce' }],
});
const reduced = await webContents.executeJavaScript(PROBE_SCRIPT);
if (reduced.enterAnimationDurationMs <= 1) { /* 真的关掉了 */ }
```

跑出来：

```

PASS 渲染层 · 入场动效实测 140ms，在 120–160ms 内
PASS 渲染层 · --text-faint 在 --bg-panel 上实测 5.32:1
PASS 渲染层 · --text-faint 在 --bg-elev 上实测 4.88:1
PASS 渲染层 · :focus-visible 规则已进入 CSSOM，共 2 条
PASS 渲染层 · .chat-scroll 实测 clientHeight=940px（真实布局，非桩）
PASS 渲染层 · Reduce Motion 下入场动效实测 0.001ms（媒体模拟真实生效）
PASS 渲染层 · Reduce Motion 前后 .chat-scroll 几何不变，动效没有参与布局
```

最后两条尤其值：一条证明减少动效真的关掉了运动，另一条证明**关掉动效不改变布局** ——
也就是说那 4px 的位移确实走的是 `transform`，没有参与布局计算。
这两句我原本只能靠"我是这么写的"来保证。

对比度那两个数字还有一个额外好处：`5.32` / `4.88` 与我改颜色时手算的结果吻合。
两条独立路径得到同一个数，比任何一条单独绿都更让人放心。

## 顺带修掉的：一个会拉假警报的"报数"

这一轮还有一件事：时间线在静默丢事件。`STATUS_CHANGED` 到
`PLANNING/EXECUTING/VERIFYING` 被当"噪音" `break` 掉，找不到 `ToolCallView`
的工具事件、重复引用、缺正文的验证事件，全都无声消失。项目有条硬不变式：
**任何截断、过滤、排除都必须显示数量和原因**。

第一版我老老实实全算进"省略了 N 条"。然后发现：`TOOL_CALL_RESOLVED`
每个工具调用都有一条，`VERIFICATION_STARTED` 每次验证都有一条 ——
一个普通的 Run 会挂上「时间线省略了 27 条事件」。

但那 27 条的内容**并没有丢**：工具调用的解析结果画在那一行的徽标和预览上，
验证开始由验证结束那一行代表，交叉审核由专门的卡片呈现。
把它们算成"省略"，等于每个 Run 都拉响一次不需要处理的警报 ——
用户很快学会无视这块区域，那时报数就等于没报。

所以分两级：

```ts
interface Omission {
  readonly level: 'omitted' | 'merged';   // 看不到的 / 已并入其他行的
  ...
}
```

`omitted` 进主标题「时间线省略了 N 条事件」，常规阶段流转可以就地展开；
`merged` 单独一行「另有 N 条事件没有单独成行，但内容已并入对应的行或卡片」。
两者都报数，但只有前者需要用户关心。

## 可以带走的

1. **"我写了这条 CSS"和"这条 CSS 生效了"之间隔着一整个浏览器。**
   解析文件文本的测试有它的位置（它挡得住手误改坏数值），但别让它假装成渲染证据。
   写这类测试时把边界写进文件头 —— 我写了，然后那句话反过来提醒我该去补什么。
2. **桩掉的东西，就是你没测到的东西。** 给 jsdom 装上 `scrollHeight`
   之后测的是逻辑，不是几何。这不是问题，前提是你知道自己测的是哪个。
3. **已经在跑的真实环境是最便宜的证据来源。** 自检本来就拉起了完整 Electron，
   加十几行 CDP 就把"样式表合同"升级成了"计算样式实测"。
4. **报数报到用户学会无视，就等于没报。** 省略披露要区分"信息丢了"和
   "内容在别的行上"——前者是警报，后者是账目。混在一起，警报就贬值了。

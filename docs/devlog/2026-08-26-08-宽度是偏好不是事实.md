# 宽度是偏好，不是事实

交互评审 v0.2 P1 的最后一片：对话 ↔ 编辑器之间的可拖分隔线。此前所有栏宽
硬编码在 CSS 里 —— 「面板位置恒定 + 用户可调」是 IDE 空间反射的两半，
P1 骨架片做了前一半，这里补后一半。

## 改了什么

- 编辑器列左缘一条 6px 抓握带（`role="separator"`，可聚焦）。三条等价的路：
  **拖拽**（pointer 事件，钳制在编辑器 ≥360px、对话 ≥400px 之间）、
  **方向键 ±32px**（键盘用户不欠一等）、**双击复位**回 CSS 默认比例。
- 宽度记在 `localStorage`（`repopilot.ui.editorWidth`）。它是纯呈现偏好：
  不进事件、不进 Core、存不了就只在本次会话生效 —— 界面偏好走浏览器存储，
  与「Renderer 无 Node/FS」的边界无关，与证据链更无关。
- 未拖过时不写内联列宽，仍走 `minmax` 比例 —— 默认行为零变化。
- focus-visible 给标准焦点环（不敢 `outline: none`，selftest 盯着焦点环规则）。

## 测试与真机

- App.layout.test：方向键调宽 → 内联列宽出现且落库；双击复位 → 两者都清除；
  测试自己收拾 localStorage（不留持久化改动）。
- 真机：合成 pointer 事件把分隔线拖到 50% 视宽 —— 列宽 720px 生效且
  `localStorage` 记住 720。

61 文件 / 1051 测试全绿，typecheck 干净，selftest ALL PASS。

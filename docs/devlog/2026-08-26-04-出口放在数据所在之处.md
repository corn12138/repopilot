# 出口放在数据所在之处

交互评审 v0.1 P0 的 #2（归档入口）当时没随 P0 落地，v0.2 复核点名（N9）。
这一片把它按仓库现实补上，并把"残留成因"查清。

## 先说清一件事：这里没有「归档」这个概念

协议里没有 `run.archive`。retention 是按**天龄**回收证据（evidenceDays），
不是按选中项。要造"选中若干 Run 归档"就得给 Core 加新概念（RunView 新字段、
持久化、鉴权、IPC）—— 那不是 P0.5 这种"纯呈现层、零合同改动"切片该夹带的。
诚实的做法：**把已有机制的出口放到用户找它的地方**，真正的选择性归档单独立项。

## 改了什么

- 侧栏历史折叠（「更早的 N 条 ▸」）里加一行安静入口：「清理历史记录 → 设置 · 数据保留」。
  点击打开设置页并**自动滚到数据保留卡**（jsdom 无 scrollIntoView，可选调用）。
  预演（preview）与逐项报数的清理界面本来就在那里，缺的只是从列表层过去的路。
- 每个打开设置页的入口显式声明滚动意图（`settingsFocus`）：普通「设置 · API」
  按钮、Welcome、Composer 的入口都不滚 —— 只有清理入口滚到保留卡。

## 残留成因（v0.1 #2 遗留问题，已查清）

selftest 的数据隔离（`REPOPILOT_DATA_ROOT` 指向一次性目录 + finally 删除）
首次落地于 f0698ef（2026-08-19）。真实数据里的 8 条 [selftest] 残留全部
落在 08-11/08-12 —— 隔离存在之前的旧版本写入。此后 selftest 不再触碰真实
data root，**不会再新增残留**；存量属于历史数据，用户可用本片的入口按
保留策略删除（预演先行、逐项报数）。

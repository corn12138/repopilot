# 并排是视图内的事，不是布局的事

验证轮收尾后用户说「继续」。排在前面的是双面板同屏对照 —— 用户最初那句
「像 Herdr 那样在一个屏幕里分区展示」到今天为止只兑现了一半：一次只能镜像一个会话。
它的前置写在计划里是「过 N12」。

## 一、先读 N12 原文，再决定要不要"过"

N12（交互评审 v0.2）说的是**空间不稳定**：开编辑器时文件树换列、主栏跳到最右、没有分隔线、
编辑器没有显式开关；§5.2 的 IA 修订把它收成一句「对话恒居中，编辑器恒在右侧舞台」。
它约束的对象是**顶层三栏**。

观察面板是主栏内的全屏视图（与设置/证据同级互斥），把两个镜像卡并排放进这个视图，
不新增 grid 列、不改任何一栏的宽度或位置 —— 这是**视图内部排版**，与 N12 无关。
结论记进了基线文档（§5.2 补注），顺带定了一条更重要的：将来的工位区（PTY 面板）若来，
同样只能作为主栏内视图或编辑器舞台的标签页，**不得成为第四列** —— 否则 N12 白修。
「过 N12」这件事本身花了十分钟；值钱的是把工位区的位置也一并钉死，免得下一刀再议。

## 二、镜像槽：谁决定谁在左边

多镜像最容易做错的地方是让 Renderer 自己记"哪几个在看"。那会出现两份真值：Main 认为在看 A、B，
Renderer 以为在看 A、C，投影推来一份 C 的，界面无处安放。所以：

- Main 的 `watches` 是一个 `Map`，**插入序就是槽位序**（先选的在左）；上限
  `OBSERVER_MAX_MIRRORS = 2` 放在 shared —— Renderer 用它写文案，Main 用它做槛；
- 满了再选，顶掉最早的；重复选已在看的，幂等，不重读不重推；
- `watch` 先推 `observer.state`（新的有序 watching）再推投影 —— Renderer **先知道往哪个槽放**；
- `unwatch` 可以只关一个（带 sessionId）或全部停止（关面板时）；
- Renderer 收到 state 就按它裁剪：不在 watching 里的投影一并丢掉，不留残影。
  唯一的例外是"投影先到、state 未到"的补位 —— 只补进列表末尾，不改序。

服务层测试钉住的东西：两个各出投影、第三个顶掉最早、状态先于投影、幂等、`pollOnce` 只服务在槛的、
会话换届时被删掉的会话从槛里移除并推状态、`unwatch` 对不在槛的 id 静默。

# 基线红了，面板没有坏

2026-09-14 跑 `pnpm probe:journals`，Claude 只有一个新增字段，Codex 却报了
`BREAKING_DRIFT`：四个曾被归入 required 的字段，现在只在部分同 type 记录中出现。

这条红灯不能直接翻译成“观察面板坏了”。同一轮真实项目干跑读了 32 个会话，
32 个都投影为 `OK`，没有 `FORMAT_UNKNOWN`。它证明的是字段快照与当前日志样本不再一致；
面板是否还能按消费契约读取，要由逐会话投影单独回答。

## 先核版本，再更新基线

现有快照采集于 2026-09-05。本轮先读本机版本：Codex CLI `0.154.0`，Claude Code
`2.1.258`；再检查 diff，只看到键名集合变化，没有把日志内容写进快照。

Codex 的四个降级字段是：

- `function_call_output.call_id`
- `item_completed.started_at_ms`
- `task_complete.duration_ms`
- `task_complete.started_at`

它们在当前真实记录里仍存在，但不再是每条同 type 记录必有。继续把它们留在 required，
会把合法变体当成格式损坏；直接删掉整个 type，又会失去仍然有效的观察信号。
所以按两层模型把它们降为 optional，并收录新增键与 `thread_goal_updated` type。

## 验证边界

执行 update 模式时，两份快照只写键名、type 名和计数。随后重新执行普通 probe，要求：

- Claude/Codex 两份快照都没有新的 breaking drift；
- 当前项目全部会话仍能投影；
- 读失败、截断、上限丢弃继续报数；
- 不读取凭据，不把会话正文写进仓库，不产生出站。

本次结果为 32/32 会话 `OK`。这说明当前基线与当前版本重新对齐，不证明未文档化日志格式
已经稳定，也不授权 P2 自动接入 desktop agent。下一次版本升级仍要重新跑同一条 probe。

# 等你输入不是任务状态

双镜像和人工交接完成后，用户仍要在会话长列表里逐个判断哪一边已经说完。`active` 的 20 秒
mtime 徽标回答的是“文件刚刚变过”，不能回答“这一轮已经结束”；拿它做等待队列会让慢工具和
刚结束的会话互相混淆。

这次复用交接门前已经存在的机器结束状态。Claude 只看 `message.stop_reason` / `terminal_reason`，
Codex 只看协议记录的最终 assistant message；后续 user 或 tool 记录会把状态降回运行中。列表只读
每个会话最多 512KB 尾部，并按 size/mtime 缓存。Renderer 在观察页打开时每 3 秒刷新，所以文件
没有变化时不会重复读取全部尾部。

界面把 `READY_TO_HANDOFF` 集中为“待你输入 / 决定”，最多展开最近 8 个；更早的待决定会话和
UNKNOWN 都显式报数。这个名字故意带“决定”：机器字段只能证明本轮结束，不能证明模型需要什么，
更不能证明任务完成。点击队列项只把对应会话放进最多两个镜像槽并定位过去，不触发传话、交接、
审批、验证或终态。

真实项目探针发现 32 个会话，25 个为本轮结束、4 个仍在运行、3 个 UNKNOWN；授权阶段增加有限
尾部检查后耗时 221ms。Electron selftest 的真实 IPC 与 DOM 显示同样 25 个待决定会话，双镜像、
冻结交接、撤销清理继续全部通过。全量测试为 75 个文件、1347 个测试，其中 6 个本机探针默认跳过。

接收方 Claude/Codex Desktop 是否给出有用回复仍是人工验收，不由自检伪造。产品继续禁止 GUI
自动化；“队列里出现”也永远不能上移为 RepoPilot 的 Run、Approval、Verification 或成功事实。

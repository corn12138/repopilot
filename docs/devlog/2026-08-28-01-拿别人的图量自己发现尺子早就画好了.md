# 拿别人的图量自己，发现尺子早就画好了

用户丢过来一张架构图（某 agent CLI 产品的 hosts / SDK / engine 三层栈），问：
「我们的 IDE 能借助图中的逻辑吗？」

我原本准备的答案是一份"可借清单"。逐项量完之后答案变成了另一句：
**图上值得借的四件，TD 里全都写完了 —— 两个月前，而且写得比图细。**
真正该记的不是"借到什么"，是这次对照暴露出来的三件别的事。

## 一、先把证据等级摆正

仓库里已有三份样本吸收评审（TabTin、Neovate-Code、A2A），每份开头都有一段
证据边界。这次的材料比它们都弱：

| | TabTin 那次 | 这次 |
|---|---|---|
| 原始材料 | 公开营销页逐字文本 | **一张图片** |
| 采集记录 | 时间戳 + 2955 字符 + sha256 + Evidence ID | **无** |
| 能引用的 | 页面逐字文字 | **只有图上的标签词** |

没有 URL、没有哈希、没装没跑没读文档，连图的真伪都没核验。所以这份材料
**不能支撑任何一句关于那个产品的事实陈述**。它只能当一份**问题清单**：
把图上每个方框念一遍，逐个去问"我们自己是什么状况"。

这个定性很重要 —— 它决定了后面所有结论的证据必须来自**我们自己**，
而不是"人家都这么干"。评审文档的结论字符串因此写成 `LENS_ONLY`。

## 二、量完的结果：4/4 已覆盖

| 图上的词 | 我方现状 |
|---|---|
| `context: frozen prefix, compaction` | **`PRD-CONV-002`（P0）+ TD §9.10**：`materialize → prune → compact` 三层、50%/10% 阈值 + hysteresis、`CompactionArtifact`、"只压缩稳定前缀，固定保留 system/policy…"。r4/r7 冻结 |
| `tools: reads overlap, writes exclusive` | **`PRD-RUN-002`（P0）+ TD §9.4**：`batch=SEQUENTIAL \| READ_PARALLEL`，"只有同一 immutable snapshot 上经证明 effect-disjoint 的 R0 read 可并行"。r7 冻结 |
| `sessions: fork` | **`PRD-FORK-001`（P1）+ TD §9.17.1**，r10 冻结 |
| hosts/SDK 边界约束 | **`PRD-SURFACE-001`（P1）+ TD §9.15 + TD-DEC-017**：多表面只能是同一 Control Plane 的受限客户端，禁止 auto-approve 与宿主回退。r7 冻结 |

四项全中，而且前两项是 **P0**。图上还有一件 `rewind`，我们更早就把它归到了
**威胁**而不是特性（`THR-SESSION-PATH-001`：整文件 JSONL 重写会断 lineage）。

所以这轮修订的第一条原则就定了：**不新增任何 Requirement。**
需求已经存在的情况下再"因为对标而新增需求"，那是文档灌水。

## 三、真正的收获

### 收获 1：一份机器证据（这个最值钱）

`PRD-CONV-002` 是 P0，**原型一行没实现**。代码核对：`agent.ts` 的
`conversation` 数组只增不减（`pushUser` 只合并末尾、从不裁剪），全文件无压缩调用。

而 08-26 真机走查的三个 Run，全部死于同一种方式：

| Run | 轮次 | token | 终态 |
|---|---|---|---|
| `run_074bde20…` | 12/40 | 227091/600000 | 规划阶段用满 12 轮未提交计划 |
| `run_9b05b52a…` | 12/40 | 162578/600000 | 同上 |
| （第三例） | 12/40 | 146.7k | 同上 |

`run_074bde20…` 的逐轮输入 token：`1206 → 3457 → 3865 → 6008 → 8639 → 11081 →
13169 → 16160 → 19693 → 22423 → 26564 → 30499 → 32207`。单调递增，26 倍。

**但因果没证。** 观测只能证明"单调增长与同型失败共存"，排除不了提示词质量、
12 轮上限设得太紧、或模型本身不会提交计划。所以证据登记里写死了
`不主张因果`，假设 `ASM-026` 的状态是 `Open` 而不是"已验证"。

即便如此，这仍是 Stage 0 的**第一份**指向"§9.10 的压缩设计是承重的、不是纸面奢侈品"
的机器观测 —— 而这恰恰是原型该干的活。AGENTS.md 写着「原型验证的是『这些设计假设
成立吗』」。这次它验证到了一条。

### 收获 2：一个文档缝里的洞

图上 `sessions: resume`。查下来：UI 断线有 `resume cursor`（TD §9.1），跨窗口有
`ConversationContinuationArtifact`（§9.10），外部 CLI 的 `旧 session resume` 是
hard deny（§9.14）—— **没有一条讨论我方 Run 自己能不能续跑**。

而实现早就选好了：`authority.ts:491` 写着「恢复出来的都是**只读**的：没有
Agent Loop、没有工作区，不能续跑」。更微妙的是 `agent.ts:1271` 的注释已经在
为这条路写防御：「半截的历史一旦被复用（**重启续跑**、交叉审核复读），两家 wire
都会返回 400」—— **代码在为一个文档没承认的场景做防御**。

这不是缺功能，是缺一个决策。落成 `Q-024`，把三个选项和各自代价写下来，
不做实现承诺，并加一句护栏：「在决定成文之前不得由实现默默扩大 —— 现状是可接受的
默认，但必须写成决策而不是副作用。」

### 收获 3：一条该冻结的拒绝

图把 `canUseTool` / `hooks` / permission modes 放在 host + SDK 侧。这在我们这儿是
**权限上移**，方向正好相反：Core 发 typed `ApprovalRequest`（带 `subjectDigest`，
参数一变审批即失效），客户端只能**提交**决定、不能**产生**决定。

我们对它的拒绝此前散落在多条不变式里（TD §4 权限边界、`PRD-SURFACE-001`、
AGENTS.md 不变式 6/9），**没有一条可引用的编号**。于是下次有人问"为什么我们不像
它那样"，就得从头辩一遍。这轮冻结成 `DEC-019` / `TD-DEC-021`，把理由写死，
连同 permission mode（"这一次跳过检查"撞 P0 无"仍然执行"）和 stdio 传输
（私有 MessagePort 意味着 Core 不监听任何端口，这是威胁模型的承重条件）。

## 四、踩了什么

**差点写成一份"新增需求"的文档。** 第一反应是列可借清单 → 每条配个新
`PRD-XXX-001`。真去 grep 才发现 `PRD-CONV-002` 和 `PRD-RUN-002` 里逐字写着同样的东西。
如果没查就写，会造出四条与现有 P0 语义重叠的需求，追溯矩阵从 87 涨到 91，
而实际能力一点没变 —— **纯噪音，还破坏了 Gate 计数的可信度**。

教训和上一轮的"全角括号假绿"是同一类：**别信自己对自己代码/文档的印象，去查。**
自己写的东西两个月后就是别人写的。

**顺手验证了这条纪律的价值**：改完跑 `verify-r10-trace.py`，
`PASS: requirement defs=87 prd_trace=87 td_trace=87`、`threats 64/64`。
机器确认了"零新增 Requirement"这句话是真的 —— 声明和事实对得上，这正是
Trace 校验器存在的意义。

## 五、可复用的结论

- **对标前先给证据分级。** 一张图和一份带哈希的采集记录，能支撑的结论强度差一个量级。
  分级写在文档开头，后面每一句都受它约束。
- **"我们能借什么"的正确问法是"我们缺什么"。** 前者向外看，容易借来一堆已有的东西；
  后者向内查，才可能查出"设计有、实现没有"这种真差距。
- **设计文档已覆盖 ≠ 产品已具备。** 这次两处落差（无压缩层、工具全串行）都不是 TD 违规
  （原型是 disposable spike，本来就不承诺符合 TD），但它们是**证据缺口**的准确位置。
- **拒绝也值得一个编号。** 散落在多条不变式里的"我们不这么干"，等于每次都要重新辩论。
  写成 DEC，附上重开条件，就把辩论变成了查阅。

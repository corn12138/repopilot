# 填一次，即永久授权

> 开发记录 · 2026-08-19 · RepoPilot

08-17 审计 D3：用户在任务输入区手填的任意 argv 被登记为验证命令，`risk` 字段**硬编码 `'R1'`**。
而这条命令会在计划批准前作为基线跑一次，之后模型还能在预算内用 `run_command` 重复调用任意次。
所以 `git push origin main`、`npm install some-pkg`、`rm -rf dist` 填进去，等价于"填一次即永久授权"。这一刀很小，但得切。

## 一、在登记之前分级，而不是执行时再拦

`commandRisk.ts`：只看 argv —— 可执行名 + 第一个子命令。R1 是构建/测试/类型/lint/本地脚本（node、tsc、vitest、
`pnpm build`、`git status/diff`…）；R2 是依赖/网络/容器（`install/add/ci`、curl、wget、docker…）；R3 是删除/覆盖/权限
（rm、mv、chmod、dd…）；R4 是 push/merge/reset/commit/publish/sudo/ssh/env/aws/kubectl。**认不出的可执行名按 R2**，
不按 R1 —— 未知二进制可能是任何东西，用户可以用 node / pnpm 等已知入口包装它。白名单比黑名单诚实。

`withUserCommands` 在登记前调 `userCommandAdmission`：只有 R1 进来；其余 `task.create` 直接拒，消息点名等级、命令、原因
（R2 多一句"原型没有一次性精确审批，所以不开放"）。e2e 钉了审计点名的三条外加 `sh -c touch marker`：
任务没建、marker 不存在；`node check.mjs` 照常。

## 二、没做的

R2 的正路是"参数绑定的一次性审批 + TTL + max uses"（PRD-APPR-006）—— 原型只有 PLAN 审批，没有 TOOL_CALL 审批 UI，
所以这里选择 fail-closed 而不是造一个假审批。`runVerification` 仍直接调 `runCommand`、不经 `dispatchTool`、不进工具账本
—— "同一 Gateway、同一账本"那一半还欠着（I-2），下一刀。

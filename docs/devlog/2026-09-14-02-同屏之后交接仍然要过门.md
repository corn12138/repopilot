# 同屏之后，交接仍然要过门

双镜像已经能把 Claude 与 Codex 放在一个观察页里，但“看得到”与“能把结论交给另一边”之间
还差三条事实：这是谁启动的会话、这一轮是否真的结束、接收方拿到的是否还是人确认的那份内容。

这次没有去嵌入 Desktop 窗口。真实日志已经给出足够的来源字段：Claude 的
`entrypoint=claude-desktop/cli`，Codex 的 `originator=Codex Desktop/codex-tui` 与
`source=vscode/cli`。列表因此按 Desktop、CLI、平台启动和 UNKNOWN 分组；字段缺失或互相冲突
就落 UNKNOWN，并把依据展示出来。

结束状态也不采用模型正文。Claude 看 `message.stop_reason` 或 `terminal_reason`；Codex 看协议记录的
最终 assistant message。后续如果又出现 user 或 tool 记录，状态会回到运行中。没有机器结束记录时，
“准备交接”按钮不可用。

交接分两步。先由 Main 从最新文件重新投影，冻结有限行数并报告省略量；再由人选择复制给另一个
Desktop，或送进 RepoPilot 的任务入口。后一条路会重新导入仓库，交接正文与 digest 同时提交，
Core 重算不一致就以 `HANDOFF_STALE` 拒绝。交接正文仍要经过任务文本 DLP，并在出站披露里作为
独立数据类别出现。这样观察通道没有获得 Task/Run 权威，现有预算、验证、补丁接受与有界交叉审核
也不用复制一套。

当前边界仍然清楚：观察是只读的，不替用户操作 Claude/Codex Desktop；“复制”只是把冻结文本放到
剪贴板；进入 RepoPilot 后是否启用第二审核方仍由用户在任务选项里决定。质量来自可追溯的交接、
真实验证与硬上限，不来自两个模型无限互相说服。

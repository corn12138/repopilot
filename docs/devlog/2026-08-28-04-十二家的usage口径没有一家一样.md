# 十二家的 usage 口径，没有一家一样

上一篇加了"缓存计费构成入账"，两个适配器各写一行解析。写的时候我心里清楚：
**字段名是凭一般知识猜的**，而我们支持 12 家 provider。所以这一轮做的事只有一件——
去每家官方文档逐条核实。

结果：**12 家里我猜对 8 家，猜错 1 家、漏掉 3 家、还有 1 家语义完全反了。**

## 语义反了的那家：Anthropic

我假设 `input_tokens` 和 OpenAI 的 `prompt_tokens` 一样，是**含缓存的总输入**。
官方文档逐字：

> `input_tokens`: Number of input tokens which were **not** read from or used to create a cache
> `total_input_tokens = cache_read_input_tokens + cache_creation_input_tokens + input_tokens`

文档给的例子：缓存读 100,000 + 新建 0 + 用户消息 50 = **总输入 100,050**。

**是相加，不是子集。** 后果比"百分比算错"严重得多——`manifest.inputTokens`
直接进预算账本（`agent.ts` 的 `chargeModelTurn`）：

```
文档的例子里，我们会把 100,050 记成 50。
```

那是一个**会失灵的止损**：预算永远花不完，Run 不会因超限而停。今天不发
`cache_control` 所以没暴露，但中转商可以替我们开（OpenRouter 对 Claude 就要求发）。

修法不是改百分比公式，是**在适配器边界归一化**：对外的 `inputTokens` 一律是
"本轮处理的输入总量（含缓存读）"，两个 wire 从此同义，上层不必知道各家口径。
钉子测试直接抄文档那个例子：`100000 + 0 + 50 → 100050`。

## 漏掉的那家：Kimi 每次都告诉我们了

Moonshot 把命中数放在 **`usage.cached_tokens`（顶层）**——既不叫
`prompt_cache_hit_tokens`，也不在 `prompt_tokens_details` 下。我的两级 fallback
一个都不匹配。

于是：**Kimi 每次都回报了，而我们每次都显示"未回报"。**

这是纪律的**反向违反**。我们一直在防的是"把未知当已知"（未回报显示成 0 命中），
这次犯的是反面——把已知当未知。同样是撒谎，只是方向相反。

## `??` 会被占位 0 截断

SiliconFlow 是唯一同时声明两套字段的 provider。`??` 只对 `null`/`undefined` 下坠，
所以如果 `prompt_cache_hit_tokens` 是未接上游的**占位 0**、真值在
`prompt_tokens_details.cached_tokens`，我们会取到 0 并显示"0 命中"——
正是明令禁止的那一格。

改成一个小函数，把两条纪律写在一处：

```ts
function reportedTokens(...candidates: Array<number | undefined | null>): number | null {
  const reported = candidates.filter((v): v is number => typeof v === 'number');
  return reported.length === 0 ? null : Math.max(...reported);
}
```

- **只有所有候选整体缺席才返回 null** —— 真实回报的 `0` 必须保留成 `0`；
- **取 max 而不是第一个非空** —— 防占位 0 截断；两套都是真 0 时 max 仍是 0。

（诚实标注：SiliconFlow 官方没说明哪套字段对哪些模型有效，取 max 是**我方的防御选择**，
不是文档背书。）

## 还有一处凭空印出的数字

```tsx
`本轮输入的 ${lastContext ? Math.round((cacheRead / lastContext) * 100) : 0}%`
```

`lastContext` 为 null（provider 没回总输入）时，这行会印出 **"0%"**——一个我们
证明不了的数字。改成算不出就说算不出：「占比未知（本轮输入未回报）」。

## "未回报"底下藏着三件不同的事

原文案是「未回报（该 provider 没给缓存构成）」。核实完发现它把责任归错了：

| 实际情况 | 该说什么 |
|---|---|
| **我方没开启** —— Anthropic 必须显式发 `cache_control`，我们不发 | 「未启用 —— 需显式发送 cache_control，我方目前不发」 |
| **该家不适用** —— ModelScope **按调用次数计费**（0.5/1/2 魔粒每次），缓存不改变费用 | 「不适用 —— 该平台按调用次数计费」 |
| **真的没给** —— 有缓存能力但这次没回这个字段 | 「未回报（该 provider 这次没给缓存构成）」 |

前两条是我方**已知**的事实。把已知的原因写成"未知"，同样是不诚实——
尤其第一条，等于把我们自己的选择说成对方的缺陷。

## 12 家的最终账

| 判定 | 家数 | 谁 |
|---|---|---|
| ✅ 本来就对 | 8 | anthropic(字段名)、openai、deepseek、zhipuai、dashscope(读)、volcengine、openrouter(读)、xai |
| ❌ 语义反了 | 1 | **anthropic**（相加 vs 子集） |
| ❌ 完全漏掉 | 1 | **moonshot-cn**（字段在 usage 顶层） |
| ⚠️ 会被占位 0 截断 | 1 | **siliconflow**（两套并存） |
| ❌ 写入字段被丢弃 | 3 | openai、openrouter、dashscope（都有 `cache_write`，我硬写了 null） |
| ❓ 查不到官方文档 | 1 | **modelscope**（无 API 参考页；且按次计费） |

`cacheWriteTokens` 还有一个**必须记住的非对称性**：Anthropic 的 `cache_creation`
是**额外项**（要加进总输入），OpenAI 的 `cache_write_tokens` 是**子集**
（官方算式 `ordinary = input − cached − cache_write`，不能加）。照搬会把总输入重复计一遍——
这条单独有测试钉着。

## 可复用的结论

- **写适配层时，"我知道这家怎么回"是最危险的自信。** 12 家里 8 家猜对，
  听起来不错——但错的那 4 家里有一家会让止损失灵，一家让功能对用户完全隐形。
- **"未知就是未知"是双向的。** 防止把未知当已知只是一半；把已知当未知
  （Kimi 那条）同样是错，而且更难发现，因为它表现为"功能好像没生效"而不是报错。
- **文案会替你归错责任。** 「该 provider 没给」在四种不同的事实上都能说得通，
  其中两种的真实原因是我们自己。
- **查不到就写查不到。** ModelScope 那格现在写的是"不适用"（因为按次计费这一点
  文档有明说），而不是编一个字段名试试看。

核实覆盖 12 家、全部一手官方文档；未找到文档说明的空白逐条记在评审里，没有猜测填空。

64 文件 / 1160 测试全绿，typecheck 干净，selftest ALL PASS。

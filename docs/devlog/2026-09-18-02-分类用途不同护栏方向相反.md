# 同一套分类，用途不同，护栏方向就相反

`isGeneratedPath` 是一条锚定 `^` 的顶层正则：只认 `dist/build/out/coverage/.vite/.turbo/.next/
node_modules` 打在开头。于是 monorepo 里 `packages/foo/dist/bundle.js` 不含顶层前缀，被当成
「人写的」混进补丁；lockfile、`*.min.js`、`*.pb.go` 一个都不认。对照 Claude Code 的
`mods/diff/hooks/classify`，它把 generated/test/noise 拆成目录段、文件名、后缀、模式四维数据，
覆盖广得多。

但照搬会踩雷。Claude 的分类只用于 diff 面板**折叠展示**——noise 折起来，展开还在，一个字节
都不丢，所以它可以激进（`.d.ts`、`vendor/`、`__snapshots__/` 全折进去）。RepoPilot 的
`isGeneratedPath` 用于**硬排除出补丁**：`changedVsBaseline()` 只让 authored 进 `PatchArtifact`。
同样一套分类，用途反过来，护栏方向就得反过来——这里激进 = 把用户真实改动静默挪出补丁正文。
`workspace.test.ts` 早就钉住了这条：`src/dist-helper.ts`、`distribution/`、`distance.ts` 必须是
authored，注释写着「被误判成 generated 就等于用户的改动被静默丢弃」。

所以我采纳 Claude 的**结构**、不采纳它的**激进度**：目录改成整段匹配（`/dist/` 这样的路径段，
不是子串），于是 `packages/foo/dist/x.js` 命中、而 `dist-helper.ts`/`distribution/`/`distance.ts`
不命中；vendored 目录（vendor/third_party/external/venv）**不纳入**硬排除，它们可能是手工维护的
源码；`.d.ts` 不算 generated（本项目 TS-first，手写 ambient 声明是源码，这是偏离 Claude 的一处）；
`.snap` 归测试不归 generated（false-green 那一维由 `coverage.ts` 单独管）。

有一处是**有意识翻转**的：`src/dist/bundle.js` 从 false 改判 true。一个名为 `dist` 的目录段在
任意深度都是构建产物的概率极高；而且它进的是 `excludedGeneratedFiles`、逐条报数，不是静默消失，
不变式 8（省略要报数）仍然成立。翻转一条被测试锁定的断言必须写明理由，我写进了断言旁的注释。

判据落到新的 `core/classify.ts`（声明式数据 + 纯函数，`isGeneratedPath` 委托它，导入方不动）。
证据：`classify.test.ts` 50 条——命中（嵌套 dist/build、lockfile、minified、pb.go、__pycache__、
target/release）与护栏（dist-helper/distribution/distance/external/vendor/*.d.ts/*.snap 必须
authored）各成组；`workspace`/`patch`/`external.normalize` 回归 120 条全绿。

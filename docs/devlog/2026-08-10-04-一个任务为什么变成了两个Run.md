# 一个任务为什么变成了两个 Run

> 开发记录 · 2026-08-10 · RepoPilot

用户发来截图：侧栏里两个一模一样的运行，标题都是「先熟悉下 我们的项目」，
一个 PLANNING，一个 EXECUTING。配文："我只发了一个任务，为啥这里有两个？"

第一反应当然是查双创建：按钮没做防抖？React StrictMode 把创建跑了两遍？

## 代码里不存在双创建路径

挨个证伪：

- 创建按钮有 `submitting` 守卫，提交中禁用；
- StrictMode 只会双跑 effect，而创建在 onClick 手势里；
- `run.updated` 事件按 runId 去重合并，不会把同一个 Run 插两次。

两个 Run 是**真的**，都是核心按正常流程创建的。问题不在创建路径。

## 真正的链条：等用户的东西，自己滚走了

同一批反馈里用户还报了另一件事：「待审批计划在这，我如果不向上滑动，
根本就看不到」。把两件事拼起来，链条就完整了：

1. 用户创建任务 → Run 进入规划 → 计划生成 → 状态变为待审批；
2. **审批卡按时间序排在时间线里**，而时间线自动滚到底部 ——
   审批卡此刻在视口上方，看不见；
3. 用户看到的是一个"没有任何反应"的界面，以为没提交成功；
4. 回到项目页，又建了一个 → 第二个走完审批进了执行。

两个同名 Run、一个 PLANNING 一个 EXECUTING，全对上了。这不是状态机 bug，
是交互设计把用户推进了误操作：**在等用户决定的东西，不能待在会滚走的地方。**

## 修复：审批停靠条 + 三处堵截

把"等你决定"的东西从时间线里捞出来，压进视口内的固定停靠条：

- 计划待审批 → 停靠条给摘要 + 拒绝 / 批准并执行 / 看完整计划（跳转）；
- 补丁待审查 → 摘要 + 跳转。**刻意不给快捷接受** —— 接受补丁值得完整
  diff 视图，一个不看 diff 的接受按钮是在制造 `ACCEPTED_UNVERIFIED`。

误操作链的另外两环也堵上：创建成功后自动跳进新 Run（不给"再点一次"留界面）；
composer 顶部提示「这个项目有一个进行中的运行」并给跳转。

### 顺带踩的坑：smooth scrollIntoView 会被静默吞掉

「看完整计划」最初用 `scrollIntoView({ behavior: 'smooth' })`。实测：
先把容器滚到底（模拟用户在时间线底部），再点跳转 ——

```
scrollTop: 11100 → 11100（没动），planTop: -10640（还在视口外一万像素）
换成默认（instant）：scrollTop: 11100 → 782，卡片进入视口
```

Chromium 里容器有未结束的滚动时，smooth 的 scrollIntoView 可能被静默吞掉。
这个按钮的全部意义是"一定能找到审批卡"，可靠性 > 动画，用 instant。

## 同一批反馈里的重构：像谁、不像谁

用户的原话是"能否做成像 Claude 那样" —— 底部输入框、模型自己选、能看用量。
照做了，但每一处都过了一遍同质化判断：**皮可以像，骨不能像。**

**整页 TaskSpec 表单 → 底部 composer。** 字段一个没删，只是重新分层。
收纳标准不是"高级/基础"，是**语义/配置**：有合理默认值的配置进抽屉
（路径、验收条件、任务类型），产品语义本体留在明面 ——

- 验证命令 chips 不收。它是「能不能说成功」的开关：不选验证命令，
  终态最多是 `ACCEPTED_UNVERIFIED`，composer 上黄字明示。这是差异化本体。
- 模型路由不收。路由会被冻结、运行中绝不自动切换 —— 选择本身是一次授权，
  授权动作不该藏在抽屉里。

**用量面板。** 模型轮次 / 工具调用 / 自修复 / token / 墙钟，全部对着
Run 的真实预算账本画进度条（超限即停、不重置）。两处刻意**不像**订阅制产品：
provider 没回报 usage 时显示「未知」而不是 0（null 表示无法证明，不等于 0）；
BYOK 模式下套餐余量在供应商侧，面板明说"这里不猜" —— 假装知道就是造数据。

**状态说人话。** `AWAITING_PLAN_APPROVAL` → 「待你审批」。带"你"字是关键：
这个状态在等的是用户，英文枚举看不出球在自己这边 —— 这正是双 Run 事故的
起点。raw 枚举收进 title，悬停可见。

## 可以带走的

1. **用户报的"bug"是现象。** 先证伪代码路径，再追交互链 ——
   这次两个 Run 都是真的，错的是界面把用户推向了第二次创建。
2. **等人的 UI 必须钉死。** 需要用户决定的东西出现在会滚走的位置，
   等于没出现；它制造的不是延迟，是误操作。
3. **收纳的标准是语义还是配置，不是高级还是基础。** 把差异化本体
   收进抽屉，产品就真的同质化了。
4. **不知道就说不知道。** 用量显示「未知」而不是 0，余量"不猜" ——
   界面上的每个数字都是一句证词。

# 窗口嵌不进来，但日志本来就在

用户的诉求演进了三轮才说清楚：先是「像 Herdr 那样把 codex 和 claude 的终端分区放一个屏里」，
然后是「不仅仅是二者的终端，是 IDE 级协作」，最后落定为「**桌面级体验包进我们的 desktop，
同屏协作观察**」。三轮各指向不同的技术底座，答错任何一轮都会把方案建在做不到的地基上。

## 一、先钉死做不到的那条路

**macOS 上没有受支持的跨进程窗口重挂。** 把 Claude.app / ChatGPT.app 的原生窗口
reparent 进我们的 Electron 窗口，不存在合法 API（不是 Windows 的 SetParent，也不是
X11 的 XEmbed）。能做的只有 ScreenCaptureKit 像素镜像（只读、要屏幕录制权限、脆），
而要**驱动**它们只能 GUI 自动化 —— `PRD-XAGENT-001` 明令禁止，connector.ts 的注释也写着
理由：既脆、又动用户登录态。

顺带把一个流行误解拆了：**Herdr 自己也不嵌桌面应用。** 它管理的是 PTY 里跑的 agent TUI。
Claude Code 的 TUI 就是那个「桌面级体验」的本体。所以「像 Herdr 那样」恰恰不需要嵌窗口。

## 二、量出来的三件事

按「动手前先量」的规矩，半天、零花费、零出站：

1. **两家的桌面会话本来就在本机留结构化日志。**
   - claude：`~/.claude/projects/<项目>/<会话>.jsonl`，最新样本 580 行、8 种顶层键形状，
     `parentUuid/message/toolUseResult/cwd/gitBranch` 都在 —— 够渲染轮次、工具调用和分支。
   - codex：`~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`，样本 124 行、
     5 种 `type`、12 种 `payload.type`（`function_call/reasoning/token_count`…），
     **包括 ChatGPT.app 里跑的会话**（每天 09:00 的 automation 记录就躺在里面）。
2. **codex 官方给观察通道发了「类型化说明书」。** 捆绑在 ChatGPT.app 里的
   codex-cli 0.149.0-alpha.4.1 有 `app-server generate-json-schema --out`，实测产出
   一整目录 typed schema（`ClientRequest.json` 等）；还有 `codex agents` 能枚举
   本机 daemon 上的全部会话。
3. **交互协议旗标在位。** claude 2.1.258 有 `--input-format/--output-format stream-json`
   加 `--include-partial-messages`（双向流）；codex `exec` 有 `--json`、`--ephemeral`、
   `--ignore-user-config`（connector 现有 argv 全部仍然有效）。
   反例一条：claude help 里**查无** `--permission-prompt-tool`，旧知识不能直接用。

## 三、撞上的禁令，正面裁定而不是绕行

「观察区 = tail 本机会话日志」听起来无害，但 `PRD-XAGENT-001` 白纸黑字禁止
「自动扫描历史会话」，TD 里还有配套的 THR-SHARED-SESSION-001（宿主登录态泄入执行链）。
差点就在禁令边上偷跑。

裁定进了 DEC-020（PRD）/ TD-DEC-022（TD），核心是**双区信任模型**：

- **平台调用域**（§7.11 Connector）：synthetic HOME、显式单凭据、拒绝宿主登录态、
  tree diff 判定 —— 一条不松。「禁止自动扫描历史会话」继续全量约束这一侧。
- **用户工位/观察域**（新 §7.15）：用户亲手用自己已登录的工具（等价于开 iTerm），
  平台零背书、零凭据代持；观察面板必须同时满足
  「按项目显式授权 + 只读 + 内容零出站 + 可撤销且撤销即清除」四条，缺一即不建。
- 两域**唯一交点**是采纳桥：人显式点「采纳」→ 平台对面板 worktree 做 tree diff →
  `WorkspaceMutationPlan` → canonical CAS。判定点从「进程退出」换成「人的动作」，
  「CLI 的话不驱动判定」原封不动。

ADR 010 也没动：工位是人驱动的观察操作，不自动在面板间转发消息；哪天要
「把 Codex 的输出自动喂给 Claude」，那一刻才进 ADR 010 的门，前置仍是 SPK-010 的
sealed A/B —— 而它还卡在 0 个 API key 上，这条瓶颈今天没有变。

## 四、落进文档的东西

- **PRD r14**：§7.15 `PRD-WKB-001..004`（工位面板 / 观察面板 / 采纳桥 / 状态徽标与
  等待队列，全部 P1 合同 / Deferred）、AC-WKB-001、DEC-020、ASM-027（日志是
  未文档化内部格式，要字段快照回归断言 —— OpenCode stdin 断言的先例直接照抄）、
  Q-027（观察授权粒度/保留/脱敏）、Q-028（真终端与「Renderer 转义 ANSI」基线的矛盾，
  硬化条款不冻结不挂 PTY）；Requirement ID 87 → 91。
- **TD r14**：`TD-CAP-WKB`、`TD-DEC-022`（PTY 宿主在 Main 不在 Core、观察投影
  volatile 对齐 `run.stream` 先例、采纳桥唯一交点、真终端是 ANSI 基线的显式例外面）、
  `TD-ASM-021`；§23 加 4 行追溯。THR 仍 64 个 —— 威胁面由既有三条 THR 覆盖，
  TEST 留待 P1 合同细化，不占位假 ID。
- **证据**：`EVI-LOCAL-SESSION-JOURNAL-001`（COLLECTED，单机单样本，弱证据；
  narrow claim 只到「存在且可解析」，稳定性与无干扰归 ASM-027 / TD-ASM-021 去验）。

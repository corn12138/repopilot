# 我说桌面端不能自动化，是错的

> 开发记录 · 2026-08-11 · RepoPilot

产品要让本机的 Claude 和 Codex 参与"一写一审"。我查了一圈，给出结论：
Codex 现在主要是桌面应用，驱动 `.app` 只能靠 GUI 自动化，合同明令禁止，所以用不了。

用户回了一句："你是说没法把 codex 包过来、拿不到评审的输出吗？"

```
$ ls /Applications/ChatGPT.app/Contents/Resources/ | grep codex
codex
codex-code-mode-host
```

## 错在哪

不在于结论"GUI 自动化不可用"—— 那条是对的，合同第 2 节写着，而且驱动 GUI
既脆弱又会动用户的登录态。

错在**取证方式**：我只查了 `PATH` 上有没有 `codex`，没有，就宣布"只能 GUI 自动化"。
这是**从缺失证据推出否定结论** —— "没装在常规位置" ≠ "不存在"。

而那个二进制是完整的：

```
$ /Applications/ChatGPT.app/Contents/Resources/codex --version
codex-cli 0.147.0-alpha.6.5

Commands:
  exec    Run Codex non-interactively
  review  Run a code review non-interactively   ← 甚至有专门的代码审查子命令
```

桌面应用 bundle 里打包一个完整 CLI 是很常见的分发方式。用它跟 GUI 自动化毫无关系，
它恰恰就是合同允许的那种"可验证的非交互 CLI"，只是随 `.app` 分发。

修法是把探测顺序改成：env 显式覆盖 → PATH 上的 CLI → **`.app` bundle 内打包的 CLI**
→ 才是纯桌面应用。新增 `BUNDLED_CLI` 形态并在界面标注"随桌面应用分发"——
升级或卸载桌面应用会让它消失，值得和独立安装的区分。

有意思的是另一半：`Claude.app` 实测**确实**不打包 CLI（`claude` 需单独安装）。
所以对它 `PRESENT_NOT_AUTOMATABLE` 仍然成立。不是为了自圆其说保留的，
是 `find` 出来的结果。

## 真正难的部分不是拉起进程，是它能看到什么

把本机的 Claude Code / Codex 拉起来当审核方，最坏情况是：它用你的登录态、
读你的 `~/.claude` 历史与 settings、顺手把宿主环境里的 `GITHUB_TOKEN` 一起带走。

合同对此有硬要求，原话是「无法用 OS 证据阻止读取真实 HOME/auth/history/settings 时
profile 保持 BLOCKED」。照搬过来，一条没打折：

- **synthetic HOME**：一次性临时目录当 `HOME`/`XDG_*`，用完即删。
  连"问一句版本"的探测也走隔离环境 —— 问版本不该成为读真实配置的借口。
- **环境整份替换，不是合并**。给的只有 PATH、synthetic HOME/XDG、最小 locale，
  以及调用方显式指定的**那一个**凭据变量。没给的就是没有。
- **没有显式凭据就拒绝启动**。绝不让它用宿主登录态跑 —— 那会静默消耗用户订阅，
  还把用户的 settings 带进审核。
- **只读**：cwd 是空的一次性目录，不挂载工作区。CLI 就算想读仓库也没有坐标系。

为此给 `runCommand` 加了受控 `env` / `stdin` 选项（复用它的超时与进程组整树终止）：

```ts
// env 显式给定时**整份替换**，不与宿主环境合并 —— 隔离的意义就在于"没给的就是没有"
const childEnv = opts.env ? { env: opts.env, droppedKeys: [] } : buildChildEnv();
```

## 隔离要用真子进程验证

替身证明不了隔离。造一个间谍 CLI，把它看到的环境和 cwd 原样吐回来：

```sh
ENVDUMP=$(env | tr "\n" ";")
CWD=$(pwd)
printf '{"verdict":"PASS","findings":[{"evidence":"%s|CWD=%s"}]}' "$ENVDUMP" "$CWD"
```

然后断言**不存在**：

```ts
expect(evidence).not.toContain('canary-must-not-leak');
expect(evidence).not.toContain('ghp_must_not_leak');
expect(seenHome).not.toBe(realHomeMarker);
expect(evidence).toContain('realClaudeDir=no');   // 宿主确实有 ~/.claude，这条才有区分力
expect(evidence).toMatch(/CWD=.*repopilot-xagent-/);
```

反向验证：把 `isolatedEnv` 退回"继承宿主环境 + 真实 HOME"——

```
× isolatedEnv：整份替换，不是合并 > 只包含明确给出的键
× 外部 CLI 看到的 HOME 不是你的真实 HOME，且 ~/.claude 那类真配置不可达
× 真实 HOME、宿主凭据、GITHUB_TOKEN 全都不在子进程环境里
× 调用结束后一次性 HOME 被删除
Tests  4 failed | 24 passed
```

四条守卫都真的在管事。

### 写测试时抓到自己一个空断言

第一版的 HOME 用例里有这么一段：

```ts
const seen = JSON.parse('{"ok":true}');
expect(seen.ok).toBe(true);      // ← 这在验证什么？
```

它绿着，但什么也没证明。改成真的从子进程输出里取 `HOME` 再比对。
一条永远绿的断言，比没有断言更糟 —— 后者至少不会给人安全感。

## 换选手不换规则

接进编排的时候有个诱惑：CLI 那条路单独写一套解析和判定。那样很快，
但"只换选手不换规则"就成了空话，两套校验迟早分叉。

所以先抽出共享的归一化，**谁来审都走这一个**：

```ts
fingerprint: digestOf({ severity, file, range, evidence: evidence.trim().slice(0, 400) })
```

指纹由平台算，**绝不采信审核方自报的**。它是"多轮之间有没有进展"的判据 ——
能被被审方操纵的话，`NO_PROGRESS` 的收敛判定就废了。CLI 交回的 JSON 也复用同一个
zod schema：换了选手不等于放宽校验，校验不过就是 `INCONCLUSIVE`，
不把半个不合法的对象当成发现。

编排层则改成注入：

```ts
export type ReviewPassRunner = (input: {...}) => Promise<CrossReviewRound>;
```

循环只管收敛语义，对"谁在审"完全无知。既有 20 条循环测试改成注入
`runReviewPass`，语义一行没动照过 —— 这说明抽象切在了正确的位置。

绑定外部 CLI 前有三道门，缺一不可，任何一道不过就降级为不审核：连接器现场探测
`READY`、vendor 与实现方**异构**（硬不变式，同厂商抛 `SAME_VENDOR_REVIEW_DENIED`，
不是"披露一下就能继续"）、有该厂商的显式凭据。

## 还没做的

- **CANDIDATE_AUTHOR 明确不做**：让外部 CLI 写代码要 disposable candidate
  workspace + single-writer epoch + normalizer，风险高一个量级。本切片只有
  READ_ONLY_REVIEWER。
- 这是 P1 合同 `external-coding-agent-cross-review.md` 的**可丢弃 spike 子集，
  不是那份合同的实现** —— 没有 connector 评审流程、没有 terms/版本准入、
  没有 network manifest、没有 resource/thermal 治理。合同状态仍是
  `P1_DEFERRED / FEATURE_DISABLED`，不因为原型跑通了就改。
- 真实双 CLI 一写一审还没跑过（本机缺 `OPENAI_API_KEY`）。

## 可以带走的

1. **"我没找到"不等于"它不存在"。** 尤其当你只查了一个位置。给出否定结论前，
   先问自己取证覆盖了几种可能的形态。
2. **判断错了要连取证方式一起改**，不只是改结论。这次修的不是"codex 能用"这一条，
   是探测顺序里少了一整类入口。
3. **隔离只能用真子进程验证，而且要写成否定式断言。** "看不到什么"比"能做什么"
   更难证明，也更值得写。
4. **接第二种选手之前，先把规则抽成共享的。** 抽象切对了的信号是：
   既有测试一行不改照过。

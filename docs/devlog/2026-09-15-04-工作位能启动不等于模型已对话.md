# 工作位能启动，不等于模型已对话

这次把 Claude/Codex 双工作位、三角色路由和人工交接点接进了产品种子。最容易写错的不是流式消息，而是能力归因：找到 bundle 只证明安装；SDK 能加载只证明 transport；新建受管会话不证明能接管 Desktop；没有真实模型回复就不能写认证通过。

Core 的手动模式在失败验证→自修复、实施→首审、审核发现→整改、整改→复审四个模型调用边界冻结带 digest 的交接工件。每次继续都重新核对 Run、Attempt、Core epoch、workspace generation、role binding、TTL 与一次性决定，Renderer 只提交冻结句柄。决定事件写不进持久化账本时不派发下一角色；自动模式仍受既有 2 审 1 改上限约束，最终接受权没有交给模型。

本机零模型探针确认 Codex app-server 可以 initialize 并创建 ephemeral read-only thread；Claude bundle 与固定 Agent SDK 版本配对可识别。Electron 隔离自检确认 Workbench preload、白名单 IPC、1440×1024 双栏和 760×900 单栏切换已接通，窄窗没有横向溢出。窗口最小宽度同步降到响应式断点以下，保证这条窄屏路径真实可达。认证、真实回复、真实取消终局和 Desktop live attach 仍是 UNKNOWN。这些空白会留在实施报告里，不用 fixture 文本补成“真实证据”。

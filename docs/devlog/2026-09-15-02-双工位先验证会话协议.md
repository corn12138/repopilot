# 双工位先验证会话协议

两栏原始日志能并排显示，却不能让用户在同一个窗口里安排谁计划、谁实施、谁评审。
接下来要验证的入口是会话协议：能不能接收输入、返回事件、处理批准和中断。
这次两家本机引擎的隔离握手通过了，真实对话与已有 Desktop 会话接管仍未验收。

## 问题是什么

现有观察页的 `ObserverSessionEntry.label` 是日志文件 basename。用户看到一串 UUID，
很难确认会话在做什么；打开后仍是日志投影，没有输入能力。冻结交接包可以进入正常任务，
但尚未形成目标中的双 Agent 工作台。

“已安装 Desktop”“能读它留下的记录”“可以启动其中的引擎”“能控制它当前的会话”
是四个不同的能力。原有 `desktopProbe.ts` 只在 Application Support 的约定子目录找内嵌
Codex，漏掉了应用 bundle 内的可执行文件，因此不能用探针的空结果否定引擎存在。

## 本次实际验证了什么

使用本机已经安装的引擎，在一次性目录和隔离配置中启动，只发协议初始化/元数据请求。
没有发送用户消息或模型请求，没有读取真实会话，也没有提取宿主凭据；结束后清理自己
启动的进程与临时运行目录。

| 对象 | 验证 | 结果 |
|---|---|---|
| Desktop 内嵌 Codex `0.154.0-alpha.6.2` | 本机协议 schema 生成 | 成功 |
| Codex stdio App Server | `initialize` | 成功，返回平台与客户端信息 |
| Codex 隔离实例 | `thread/loaded/list`、限定临时 cwd 的 `thread/list` | 均成功、各返回 0 项 |
| Desktop 内嵌 Claude `2.1.260` | bare、无工具、无会话持久化的双向 stream-json 初始化 | 收到 `control_response`，`subtype=success` |
| Codex 已有默认共享 daemon | 查询版本 | 默认 control socket 不存在 |
| Desktop GUI 实机交互 | 本机控制工具 | `Sky Computer Use native pipe startup failed`，未验收 |

Claude 初始化只保存响应形状，没有记录 account 内容。两次握手证明可以建立结构化客户端，
尚不证明认证、真实模型回复、取消对账或已经控制 Desktop 中原来的会话。

## 接入方案如何改变

[Codex App Server](https://learn.chatgpt.com/docs/app-server) 提供供自有客户端使用的会话、
批准和事件接口。本机 schema 应优先于文档中可能较新的字段；首个接入切片优先 stdio。

[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 提供引擎级编程接口。
正式适配优先公共 SDK；本次直接控制帧只用于验证安装的引擎是否响应。
[Claude 的会话文档](https://code.claude.com/docs/en/sessions) 说明 Desktop 有独立历史，
因此新建 SDK 会话必须明确标注，不能叫作“已接管原 Desktop”。

工作台将按“项目 → 任务 → 两个角色”组织，同屏显示计划/评审方和实施/修正方。
主题名、阶段、改动与下一步动作在前，协议来源与原始日志在详情里。已有 Desktop 会话
保留观察入口；实际支持控制后再开放输入，而不是把输入框画出来就算接通。

受管任务后续复用 Core 的 `runCrossReviewCycle`：最多 2 次评审、1 次修正，
候选变更走既有归一化与 CAS，平台独立验证，用户最终决定是否接受。观察 watcher 不获得
自动传话权，也不负责宣布任务成功。

## 容易混淆的地方

不能嵌入原生窗口，不足以推出只能读取日志；协议接口也可能提供交互能力。
同样，协议初始化通过，不足以推出认证与真实任务已经跑通。

进程是否由平台启动也不能独自决定全部能力。新建受管会话容易限定所有权；连接已有
会话则需要另验控制通道、准确身份、并发占用和拒绝行为，不能拿 resume/fork 偷换 attach。

“自动交接”和“模型宣布成功”也不是同一件事。经批准的有界任务可以自动推进阶段，
但仍必须保留工作区、出站、验证与最终接受边界。

## 下一项验收

先修连接能力与会话身份，再完成一个真实输入/流式输出/取消的工作位，扩成双工位，
最后串起计划确认和有界交接。已有 Desktop 活跃会话控制单列验证，失败时保留观察状态。

本轮交付是设计与接入入口验证，未修改产品运行逻辑，不构成 Stage 0 通过，
也未启动 SPK-010 或证明双模型开发已有质量收益。

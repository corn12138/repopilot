# "没给出结论"，被显示成"通过了"

我本来在评估要不要把一写一审接到 A2A 协议上。
让两个 agent 一个论证该接、一个论证不该接，反方在举证时顺手引了一行我们自己的代码。
那行代码不该长成那样。

## 问题是什么

交叉审核的收敛循环里，第 1 轮审核完是这么判的：

```ts
const blocking1 = round1.findings.filter((f) => f.blocking);
if (round1.verdict === 'PASS' || blocking1.length === 0) return done('REVIEWER_PASSED');
```

`verdict` 只有三个值：`PASS` / `CHANGES_REQUESTED` / `INCONCLUSIVE`。
而 `INCONCLUSIVE` 在三个地方产生，每一处都写得很克制：

```ts
// authority.ts —— 外部审核方输出不可解析
// 拿不到结论就是拿不到 —— 记 INCONCLUSIVE，绝不当作"没有发现"
return { ...round, verdict: 'INCONCLUSIVE' as const, findings: [] };

// authority.ts —— schema 校验不过
return { ...round, verdict: 'INCONCLUSIVE' as const, findings: [] };

// agent.ts —— 模型用满 8 轮没调 submit_review
// 用满轮次还没提交：记为 INCONCLUSIVE，不编造发现
return { ..., verdict: 'INCONCLUSIVE', findings: [] };
```

三处都拒绝编造 findings，所以 `findings` 是空的。
然后空 findings 撞上 `blocking1.length === 0`，收场变成 `REVIEWER_PASSED`。
渲染层最后一棒：

```ts
const STOP_REASON_LABEL: Record<string, string> = {
  REVIEWER_PASSED: '审核方未发现阻断问题',
```

**审核方没看成，界面告诉用户"审核方未发现阻断问题"。**

更难受的是隔壁。`external/connector.ts` 里有整整一段注释在堵一条同形的路：

> findings 读不全时，只有 `verdict === 'PASS'` 才允许把它归零，否则整份判不可解析
> —— 因为 `CHANGES_REQUESTED` + 读不出的 findings 会被下游 `blocking.length === 0`
> 判成"审核方没提意见"。

作者已经预见到"空 findings 会被误读成没意见"，在解析层堵住了 `CHANGES_REQUESTED`
那一支，然后 `INCONCLUSIVE` 从旁边走了过去。

还有第二个洞，在同一行里：`round1.verdict === 'PASS'` 是**或**的左半边。
模型返回 `{verdict: 'PASS', findings: [一条 CRITICAL blocking]}` 时，
整个 findings 数组被短路掉，不整改、直接判通过。

## 怎么解决的

判据拆成一个函数，把两条规则写在同一个地方：

```ts
/**
 * 一轮审核该怎么收场 —— 只在"没有阻断项"时才轮到 verdict 说话。
 *
 * 1. 有阻断项就整改，不管 verdict 写的是什么。verdict 是模型对自己这轮的一句总结，
 *    findings 是它逐条列出来的证据；`PASS` + 一条 CRITICAL 阻断项时，可信的是后者。
 * 2. 零阻断项时区分两种成因：`INCONCLUSIVE` 是"没看成"，不是"看过了没问题"。
 */
function verdictOutcome(round, blocking): 'REMEDIATE' | 'REVIEWER_PASSED' | 'REVIEWER_INCONCLUSIVE' {
  if (blocking.length > 0) return 'REMEDIATE';
  return round.verdict === 'INCONCLUSIVE' ? 'REVIEWER_INCONCLUSIVE' : 'REVIEWER_PASSED';
}
```

这条原则在这个仓库里已经写过一遍了，就在同一个文件下面几十行：

```ts
// 进展判定用平台算的指纹，不用模型的自我评价
```

`blocking.length` 是平台数的，`verdict` 是模型说的。同一条原则，之前只落在一处。

新的 `REVIEWER_INCONCLUSIVE` 不只是换个标签，它有三个不同的行为：

| | `REVIEWER_PASSED` | `REVIEWER_INCONCLUSIVE` |
|---|---|---|
| 文案 | 审核方未发现阻断问题 | 审核方未给出可用结论 —— 这不是"通过" |
| 事件流 | `交叉审核结束（REVIEWER_PASSED）` | `交叉审核结束（REVIEWER_INCONCLUSIVE）` |
| 续期入口 | 关（没有可续的东西） | **开** |

第三行是我改的时候才想明白的。原来折进 `REVIEWER_PASSED`，用户不但看到一个假的"通过"，
**连重跑的按钮都没有** —— 而"没拿到结论"的下一步恰恰就是再跑一轮。

## 顺带补上的第二个洞：外部 CLI 出站没有运行期闸门

同一轮取证里还翻出来一条。`ModelGateway` 那条路上，每一次调用前都要过 preflight：

```ts
if (input.purpose !== 'CONNECTIVITY_TEST') {
  if (!input.consent) return 'CONSENT_MISSING';
  if (!input.consent.resolutionDigests.includes(resolution.digest)) return 'CONSENT_STALE';
}
// route 漂移检测：profile 在冻结之后被改动过就必须阻断，而不是静默改走新配置
if (current !== resolution.digest) return 'ROUTE_DRIFT';
```

而外部 CLI **完全不经 gateway**。它的 PREFLIGHT 只有三样：连接器 READY、apiKey 非空、prompt 过 DLP。
也就是说 `task.create` 那一次比对之后，到真正 `spawn` 之间发生的一切，无人过问。

想装这道闸时才发现装不上 —— 披露里外部选手压根没有可比对的东西：

```ts
// egress.ts（旧）
resolutionDigest: null,   // EXTERNAL_CLI 两处都是 null
...
export function consentedResolutionDigests(d) {
  return d.destinations.map((x) => x.resolutionDigest).filter((x) => x !== null);
}
```

外部选手对"同意覆盖了哪些目的地"这个集合的贡献是 **0**。
用户点头的那份披露，对拿到 `REPOSITORY_FULL_COPY_VIA_CLI`（整仓副本）的那个选手
没有任何运行期约束力。

它没有网络 route，但它有身份——连接器早就算好了：

```ts
identityDigest: digestOf({ binaryPath, version }),   // 换二进制或升版本，这个值就变
```

于是：披露里填 `identityDigest`，spawn 之前**现场重探**一次再比：

```ts
private assertExternalEgressConsent(record, connector, role) {
  if (!record.consent) throw platformError('POLICY_DENIED', `${label} 没有出站同意记录`);
  /*
   * 现场重算身份，不用绑定时那份。绑定时的 profile 是 task.create 当下的快照；
   * 要挡的恰恰是"从那时到现在变了什么"，拿旧快照去比等于自己跟自己比。
   */
  const now = probeConnector(descriptor);
  if (!record.consent.resolutionDigests.includes(now.identityDigest)) {
    throw platformError('POLICY_DENIED', `${label} 与你同意的那份披露不一致（可执行文件路径或版本已变）`);
  }
}
```

闸门放在 `exportCandidate()` **之前**——拦下来的时候，一个 candidate 目录都别建。

e2e 长这样：正常创建任务（披露冻结的是 `fakecodex 0.0.1`），然后在批准计划之前
把那个假 CLI 重写成 `9.9.9`，再批准：

```ts
expect(done.statusReason).toMatch(/披露不一致|路径或版本已变/);
expect(candidateDirsUnder(runId)).toEqual([]);   // 零 candidate
expect(done.workspaceGeneration).toBe(0);        // 主线没动
expect(existsSync(promptLog)).toBe(false);       // 简报根本没送出去
```

## 踩了什么坑

### 一、我差点只改 INCONCLUSIVE，放过旁边的 `PASS`

第一版补丁是这样的：

```ts
if (round1.verdict === 'INCONCLUSIVE') return done('REVIEWER_INCONCLUSIVE');
if (round1.verdict === 'PASS' || blocking1.length === 0) return done('REVIEWER_PASSED');
```

看着挺对，跑了也绿。但 `verdict === 'PASS'` 短路 findings 那半边原封不动 ——
**它和我正在修的是同一个 bug**：都是"模型的自评压过了平台能数的东西"。
只修其中一半，等于承认这个模式在另一半是可以接受的。

改成先看 `blocking.length` 再看 verdict 之后，两条一起没了，而且规则反而更短。
现有的两条测试（`PASS + []` → passed、`CHANGES_REQUESTED + 零阻断` → passed）
一个字都不用改就还是绿的 —— 这是个好信号：新规则是旧规则的**超集**，不是替换。

### 二、想装闸门，发现没有可比对的东西

`assertExternalEgressConsent` 写完第一版，逻辑是对的，但它永远不会触发 ——
`consentedResolutionDigests` 过滤掉 null，外部选手一条都进不去，
`includes()` 永远返回 false，等于把所有外部调用全拦了。

我一开始的反应是"那就跳过外部选手的检查"。这正好是错的方向：
**检查形同虚设的原因不是检查太严，是数据源是空的。** 该修的是 `egress.ts`。

修完之后顺带白捡一个能力：披露 digest 现在对 CLI 版本敏感了，
用户升级 Codex 会让旧的同意自动失效——这与"路由一变 digest 就变"是同一条规矩，
只是外部这条路上一直漏掉了。

### 三、旧测试的标题里写着旧结论

改完 `egress.ts` 后红了一条：

```
× 外部 CLI 作者：channel=EXTERNAL_CLI、origin=null、数据类别含整仓副本；不贡献路由 digest
```

标题最后五个字就是我刚推翻的那件事。
它当时的**意图**是对的——"外部 CLI 不经网关，所以不贡献网关路由 digest"。
变的是 `consentedResolutionDigests` 的语义：它不再是"网关路由集合"，
而是"同意覆盖的目的地身份集合"。

所以不是把断言数字改掉了事，而是把标题里那个过时的结论摘掉，
再单独加一条说明新语义的用例，外加一条证明 digest 对版本敏感的。
**测试标题是会过期的文档**，改断言而留着标题，下一个人读到的就是假的。

### 四、这个 bug 是查一个跟它无关的问题时掉出来的

我在评估 A2A，让反方去找"我们的护城河到底靠什么成立"。
它为了论证"协议层拿不到比自述更强的事实源"，
去引我们自己那条"拿不到结论就是拿不到"的注释——
然后引着引着发现，注释算得很honest，下游把它折掉了。

**让人（或 agent）去论证一个跟这段代码无关的命题，比让它"review 这段代码"更容易挖出东西。**
review 会顺着作者的意图读，论证会逼它检查意图有没有兑现。

## 可复用的结论

- **空集合有两种成因，永远要问是哪一种。** "没找到问题"和"没找成"在数据上都是
  `length === 0`，在语义上是反的。折成同一个分支，就是在制造假绿。
- **同一条原则要在所有落点上都写一遍。** "平台算的 > 模型自评"在这个文件里
  已经写过（指纹判进展），但 verdict 那一行没跟上。一条原则只落一处，就是没落。
- **修一半比不修更危险。** 它会让剩下那一半看起来像是"经过考虑保留的"。
- **闸门永远不触发，先怀疑数据源是空的**，别急着放宽闸门。
- **测试标题会过期。** 改断言时把标题里的旧结论一起摘掉。

它们现在就在，而且是我们自己最在意的那一类。

# 开源前我从仓库里删掉了什么

> 开发记录 · 2026-08-07 · RepoPilot
> （这件事发生在当天下午，比前五篇晚，补记）

把一个做了一天的项目推成 public 仓库，`git init && gh repo create --public --push`
三条命令就完事了。但这三条命令是**不可逆**的 —— 推上去的东西会被爬虫索引、
被 fork、被存进各种镜像站，你后来 `git rm` 也没用。

所以推之前我做了一轮扫描。找出来的东西比预想的多。

## 一、真正的敏感内容

`docs/` 目录里躺着这些：

```
docs/source/interview/上次面试对话记录.docx
docs/source/job-description/代码智能体工程师-JD-01-工作内容.jpg
docs/source/job-description/代码智能体工程师-JD-02-任职要求.jpg
docs/source/job-description/代码智能体工程师-JD-03-加分项.jpg
docs/interview-prep/RepoPilot-AI-Agent岗位能力与工程证据映射-v0.1.md
```

一份真实的面试录音转写，三张某公司 JD 的照片，一份个人求职材料。

这些是这个项目的**起点**（整个 RepoPilot 就是从一次面试复盘长出来的），
所以它们理所当然地待在 docs 里。正因为理所当然，才容易在 `git add -A` 时
一起飞出去。

顺带一提，那份求职材料里还有一行：

```
/Users/<用户名>/Desktop/vue2:vue3:react源码的剖析/源码解析学习/00-源码全景与学习路线.md
```

另一个私人目录的完整路径（本文里出现的宿主路径和邮箱都做了脱敏 ——
这篇文章本身也是要推到 public 仓库的）。

## 二、提交邮箱里的手机号

这条是我扫的时候才想起来查的：

```bash
$ git config --global user.email
153xxxxxxxx@163.com
```

**邮箱前缀是手机号。**

Git 提交历史里的作者邮箱是公开的，`git log` 一敲就有，GitHub 的 API 也直接返回。
爬 GitHub 提交历史收集邮箱是很成熟的灰产。而且这东西**推上去就洗不掉了** ——
改 history 要 force push，而 fork 和缓存里的旧对象还在。

解法很简单，但得在第一次 commit 之前做：

```bash
git config user.email "corn12138@users.noreply.github.com"   # 仓库局部，不动全局
```

GitHub 认这个 noreply 地址，提交照样计入你的贡献图。

## 三、扫描本身

```bash
# 密钥
grep -rInE "sk-[A-Za-z0-9_-]{16,}|gho_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----" \
  --include="*.ts" --include="*.md" --include="*.json" \
  --exclude-dir=temp --exclude-dir=node_modules .
```

唯一命中是我自己写的假串 `sk-ant-selftest-ABCD1234`（用来测凭据处理的），
留着无所谓。

```bash
# 宿主绝对路径
grep -rIn "/Users/$(whoami)" --include="*.md" --include="*.ts" .
```

这条命中了 **20 多个文件** —— `docs/evidence-index.md` 里每一条证据记录都带
`cwd: /Users/<用户名>/...`。它泄露的是 macOS 用户名，而很多人的 macOS 用户名
就是真名拼音。不算严重，但它会把一个匿名的 GitHub 账号和真名连起来。

最后我把整个 `docs/`（除 `devlog/`）都排除了，这些路径也就一起没发。
`.gitignore` 里用的是这个模式：

```gitignore
# Stage 0 设计文档暂不公开
docs/*
!docs/devlog/
```

`docs/*` 排除目录下所有内容，`!docs/devlog/` 把这一个子目录重新包含回来。
注意不能写成 `docs/**` —— 那样父目录被排除后，子目录的反选不生效。

## 四、一个非敏感但会毁掉仓库的坑

扫描完准备提交，`git add -A` 蹦出这个：

```
warning: adding embedded git repository: prototype/fixtures/vite-react-broken
hint: You've added another git repository inside your current repository.
hint: Clones of the outer repository will not contain the contents of
hint: the embedded repository...
```

测试 fixture 是一个自带 `.git` 的小仓库（端到端测试需要它有 git 历史）。
外层 `git add` 一个含 `.git` 的目录时，会把它记成 **gitlink**：

```bash
$ git ls-files -s prototype/fixtures/
160000 0b5c9d35ea6d... 0    prototype/fixtures/vite-react-broken
```

`160000` 是 submodule 模式。但仓库里**没有** `.gitmodules`，所以 clone 下来
那个目录是**空的** —— 端到端测试直接废掉。

`.gitignore` 挡不住这个。我试过写 `prototype/fixtures/*/.git/`，没用 ——
git 在 add 目录时就检测 `.git` 的存在，跟 ignore 规则无关。

正确的修法是让仓库里那份 fixture **永远不带 `.git`**，改由测试在**临时副本**里
初始化：

```ts
/**
 * 把 fixture 复制到临时目录，在**副本**里初始化 git。
 *
 * 两个理由：
 *   1. 仓库里那份不能带 .git —— 嵌套 git 仓库会被外层当成损坏的 gitlink。
 *   2. 测试要断言「宿主仓库全程没被写过」，跑在副本上才不会有污染源仓库的风险。
 *
 * node_modules 用 symlink 复用，不复制 —— 几百 MB 拷不起。
 */
function materializeFixture(): string {
  const dir = mkdtempSync(join(tmpdir(), 'repopilot-e2e-'));
  cpSync(FIXTURE_SOURCE, dir, {
    recursive: true,
    filter: (src) => !/(^|\/)(\.git|node_modules)$/.test(src),
  });
  symlinkSync(join(FIXTURE_SOURCE, 'node_modules'), join(dir, 'node_modules'), 'dir');
  // 在副本里 git init + commit …
  return dir;
}
```

副作用是测试变严谨了：那条「宿主仓库全程未被写入」的断言现在跑在副本上，
不再有污染源 fixture 的风险。

清理索引里残留的 gitlink 记录还得用 `-f`：

```bash
git rm --cached -f prototype/fixtures/vite-react-broken
git add prototype/fixtures/
```

## 六、顺手重写的 README

原来的 `README.md` 是 Stage 0 的治理状态文档，通篇 `Gate=Not Ready`、
`ADR 015 User-directed Proposed Baseline`，而且引用了一堆不公开的 `docs/` 路径
—— 发出去全是死链。

公开仓库的 README 是门面，得回答三个问题：这是什么、怎么跑、**什么还没做**。
第三条最容易被跳过，但它决定了别人对项目的信任度。我列了五条：

> - **隔离强度**：`utilityProcess` + 子进程**不是**容器沙箱。`node_modules` 目前是
>   宿主的 symlink，构建脚本以你的用户权限运行。这是明确接受的残余风险。
> - **持久化**：Run 事件是 JSONL，没有加密、没有保留期、没有级联清理。
> - **崩溃恢复**：事件日志能重放，但 Core 重启后不会自动恢复进行中的 Run。
> - …

（后面两条第二天就打脸了，见
[写了不能读的日志，不叫证据](2026-08-08-02-写了不能读的日志不叫证据.md)
和 [删除也要诚实](2026-08-08-04-删除也要诚实.md)。这也挺好 ——
说明「还没做」那一节是真的在跟踪现状，不是免责声明。）

`AGENTS.md` 也一起改了：它原本写着「Stage 0 通过前不进入业务代码实现」，
跟一个已经有 10000 行代码的仓库直接矛盾。

## 可以带走的

1. **推 public 之前先 `git config user.email` 看一眼。** 很多人的 git 邮箱是
   手机号或工作邮箱，而这个字段推上去就洗不掉。
2. **项目的「起点材料」最容易漏。** 面试记录、JD 截图、竞品资料躺在 docs 里
   太理所当然了。
3. **`.gitignore` 挡不住嵌套 `.git`。** 那会变成损坏的 gitlink，clone 下来是空目录。
   要么删掉嵌套的 `.git`，要么根本别把它放进仓库。
4. **`docs/*` + `!docs/devlog/` 才能做「排除目录但保留一个子目录」**，
   写 `docs/**` 不行。
5. **推完之后查远端的实际文件树**，不要只信本地 `git status`。
